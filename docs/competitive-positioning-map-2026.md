# 競合ポジショニングマップ — 直接競合 × 間接競合 × 勝利条件

> 作成: 2026-06-03
> 目的: 「国内 SaaS＋証明の競合不在」という主張を、間接競合を含めた構造的根拠に置き換える
> 前提資料: `docs/competitor-analysis-2026-05.md` / `docs/research/automotive-onchain-landscape-2026-05.md`

---

## 0. なぜこのドキュメントが必要か

`docs/competitor-analysis-2026-05.md` は **Shopmonkey / Tekmetric / Shop-Ware という米国直接競合** の比較で完結しており、以下が欠落している:

1. **間接競合 A: 国内既存業務システム** — コーティング/PPF 店が現在使っている Excel・紙台帳・汎用業務 SaaS
2. **間接競合 B: 車両データ企業 (Carfax 型)** — 中古車流通・保険査定で Ledra が将来ぶつかる情報インフラ
3. **勝利条件の定義** — 「競合がいない」から「どう勝つか」への移行

---

## 1. 競合全体マップ

### 1-1. 競合の4層構造

```
[ L1 直接競合・海外 SaaS ]
  Shopmonkey / Tekmetric / Shop-Ware
  → 国内未展開。ただし将来の参入リスク。

[ L2 直接競合・国内 ]
  現時点で「証明書 × 保険連携 × ブロックチェーン」を同時に持つ国内プレイヤーは確認できない。
  ただし以下の隣接プレイヤーが間接的に同じニーズを押さえに来る可能性がある。

[ L3 間接競合 A: 国内既存業務システム ]
  コーティング/PPF 店が今使っている代替手段。Ledra の「置き換え対象」。

[ L4 間接競合 B: 車両データ・情報インフラ企業 ]
  中古車流通・保険査定で Ledra が将来ぶつかる「データプラットフォーム」。
```

---

## 2. ポジショニングマップ

### 2-1. 2軸の定義

```
Y軸 (縦): ワークフロー統合度
  上 = 施工・整備の現場オペレーション全体を管理
  下 = 単一機能・データ参照のみ

X軸 (横): 信頼性・証明の強度
  左 = 業務効率化・社内完結
  右 = 外部への証明・改ざん不能・エコシステム接続
```

```
          ワークフロー統合度 (高)
                  │
    Shopmonkey    │         ★ Ledra
    Tekmetric     │      [証明書 × オペ × エコシステム]
    Shop-Ware     │
    (米国 SaaS)   │
                  │
─────────────────────────────────────────── 信頼性・証明
 業務効率化       │                          強度 (高)
 社内完結         │
    kintone       │     CarSensor / Goo-net
    Excel/Access  │     JCIC / J-AutoPlatform
    moneyforward  │     Carfax(米)
    工場系 SaaS   │
                  │
          ワークフロー統合度 (低)
```

**Ledra の位置**: 右上象限。国内で唯一この象限を占める。

## 3. 間接競合 A: 国内既存業務システム

コーティング/PPF 店が実際に使っている「今の代替手段」。Ledra はここを置き換えに行く。

| プレイヤー | 実態 | Ledra との関係 |
|---|---|---|
| **Excel / 紙台帳** | 施工記録・顧客管理を Excel や紙で管理。国内中小店の 7〜8 割の推定現状。 | 最大の「置き換え対象」。移行障壁は低い (習得コスト・費用感) が、変化への抵抗感が壁 |
| **kintone** (サイボウズ) | カスタマイズ可能な業務 DB。一部の店舗や代理店が顧客管理に利用。¥1,500〜/月 | 証明書・保険連携・ブロックチェーンは完全不在。Ledra 差別化が明確。ただし「業務改善ツール」として定着している場合は移行説得が必要 |
| **moneyforward / freee** | 請求書・会計管理。コーティング業界でも小規模店が利用。 | 業務管理レイヤーは競合するが、施工証明書・保険連携は対象外。**共存が現実的** (Ledra → freee 会計連携として取り込む) |
| **汎用整備 SaaS (オートサービス、カーコン等)** | 国内の整備工場向け SaaS が複数存在。コーティング業界固有には対応していない。 | 機能的に近いが「コーティング/PPF 専業」設計ではない。施工証明・NFC・Polygon アンカリングは不在 |
| **LINE 公式アカウント + Google スプレッドシート** | 顧客通知を LINE、施工記録を Google スプレッドシートで運用。小規模店でよく見られる。 | Ledra は LINE 連携済みで「今の運用を活かしながら証明書機能を追加」という導入提案が可能。摩擦最小化の入口 |

**対 L3 の勝利条件 (§5 で詳述)**:
- 移行コストの問題ではなく「証明書を持てるか否か」のバリュープロポジション転換
- 「今の仕事のやり方を変えなくていい + 証明書だけ自動発行」が入口

## 4. 間接競合 B: 車両データ・情報インフラ企業 (Carfax 型)

保険査定・中古車流通で Ledra の将来の主戦場にいるプレイヤー。

| プレイヤー | 実態 | Ledra との関係 |
|---|---|---|
| **Carfax** (米国) | 走行距離・事故歴・整備歴を VIN ベースで提供。北米中古車流通のインフラ。国内直接展開は限定的。 | **参照モデル**。Ledra が証明書エコシステムを育てると「Carfax の日本版施工特化型」になれる。競合ではなく目指す姿。 |
| **CarSensor** / **Goo-net** (リクルート / プライムユニコーン) | 日本最大の中古車情報ポータル。車両情報・価格査定・保険比較を提供。 | 現時点では Ledra と直接競合しない。**将来シナリオ**: 中古車プラットフォームが「施工証明あり」を査定付加価値に取り込む場合、Ledra が証明書データの供給元になるか競合になるかが分岐点。**早期に API 提供側として接触**が優先。 |
| **JCIC (日本信用情報機構) 類型** / 車両査定インフラ | 保険会社や金融機関が参照する車両評価基盤。大手損保は自社のデータベースを持つ。 | Ledra の「証明書 × 保険会社 API」は、このデータ基盤に乗れるか乗れないかで価値が変わる。損保ジャパン Lighthouse 接続が成立すれば Ledra データが「保険査定の入力」になる。これが最大の堀。 |
| **J-AutoPlatform** (旧 MOTAS 延長線) | 国交省の車検証電子化基盤。2023年〜 IC チップ化。 | 法定データの管理者。Ledra は「法定車検証データ + Ledra 施工証明」の合算タイムラインを提供できれば差別化。OCR 連携済みが強み。 |
| **Toyota Vehicle History 相当** (MOBI 系) | `docs/research/automotive-onchain-landscape-2026-05.md` §3 の Toyota Blockchain Lab が狙う車両パスポート構想。現状はテックペーパー段階。 | 2〜3 年後に商用化すると、Ledra の施工記録を「OEM 側のパスポートに書き込める API」として位置づけるか、競合として対峙するかが分岐。**MOBI 加盟 + Toyota Woven City PoC が「先に現場記録を押さえる」防衛線**。 |
| **SORACOM / データホライゾン 型 IoT データブローカー** | コネクテッドカーのテレマティクスデータ仲介。走行データ・診断データを保険/金融に販売。 | 施工記録というオフライン作業データは OBD・テレマティクスと相補的。競合ではなく**統合先候補**。長期的には「テレマティクス + 施工証明」が融合した車両パスポートになる。 |

## 5. 勝利条件の定義

「競合がいない」は **ゼロイチの事実確認** に過ぎない。勝利条件は **「競合が出てきても守れる堀をいつまでに何で作るか」** で定義する。

### 5-1. 対 L3 (国内既存業務システム) の勝利条件

| 勝利条件 | 指標 | 期限 |
|---|---|---|
| **コーティング/PPF 専業店でのデファクト化** | 対象市場 (国内コーティング/PPF 専業店 推定 3,000〜5,000 店) のうち 30% が Ledra 使用 | 2027年末 |
| **移行摩擦の最小化** | LINE 連携・Google Calendar 連携・既存 Excel インポート機能により、導入 1 日以内での稼働率 ≥ 80% | 2026年 Q3 |
| **証明書の業界標準化** | 大手代理店・保険会社 1 社が Ledra 証明書フォーマットを「受理可能」として明示 | 2026年末 |

### 5-2. 対 L4 (車両データ企業) の勝利条件

| 勝利条件 | 指標 | 期限 |
|---|---|---|
| **施工記録データの一次保有者になる** | 証明書累計発行数 10 万枚達成 (中古車流通・保険会社が「参照したい」と思う規模感) | 2027年 Q2 |
| **CarSensor / Goo-net への API 提供側になる** | 大手中古車ポータル 1 社以上と「施工証明あり」表示連携の PoC 合意 | 2027年末 |
| **保険会社との双方向データ接続** | Lighthouse 保険会社 1 社で「証明書データが保険査定フローに組み込まれた状態」の本番稼働 | 2026年末 |
| **Toyota / MOBI パスポートへの記録 API として採用** | OEM PoC 合意 1 社 (§4 J-AutoPlatform / TBL との接続を含む) | 2027年 Q1 |

### 5-3. 対 L1/L2 (米国 SaaS の国内参入) の先行防衛条件

米国 SaaS が国内参入するとすれば最短 2〜3 年。それまでに作る堀:

| 堀 | 内容 |
|---|---|
| **日本固有データ統合** | 車検証 OCR、CloudSign、LINE、特商法、法人番号連携は米国 SaaS が複製に 1〜2 年かかる |
| **保険会社 × 代理店エコシステム** | Insurer ポータル + Agent ポータルの双方向ネットワークは「先に組んだ側が維持される」構造 |
| **Polygon アンカリングの証明書発行数** | 改ざん不能な記録の累積数は後発が追いつけないデータ堀 |
| **コーティング/PPF 専業特化の UX** | Shopmonkey/Tekmetric は汎用整備向け。コーティング業界の施工工程・品質基準・資材管理に最適化された UX は差別化が持続する |

## 6. 競合スライド推奨構成 (ピッチデッキ・営業資料用)

「競合なし」スライドをそのまま使うと投資家・保険会社に「調査不足」と読まれる。以下に置き換える。

### 推奨: 2x2マトリクス + 説明文

```
【競合ポジショニング】

          ワークフロー統合 (高)
                  │
   Tekmetric  ●  │  ◆ Ledra
   Shopmonkey ●  │  [唯一の右上象限]
                  │
──────────────────────────── 証明・信頼 (強)
                  │
   Excel/紙  ●   │    ● Carfax型データ企業
   kintone   ●   │      (CarSensor/Goo-net等)
                  │
          ワークフロー統合 (低)
```

**補足テキスト案**:
> 「直接競合 (Tekmetric/Shopmonkey 等) は米国市場に閉じており、証明書・保険連携は対象外。
> 国内は Excel・紙台帳が大半で業務 SaaS 化自体が未達成。
> 車両データ企業 (CarSensor/Goo-net) はデータ参照に特化し施工オペは対象外。
> Ledra は施工オペ × 証明書 × エコシステム接続を同時に持つ唯一の実装。
> 勝利条件: 2027年末までに証明書発行 10 万枚・保険会社 1 社本番稼働・中古車ポータル 1 社 API 連携。」
