# Ledra × 自動車ローン「信用回復ローン」— パートナー連携の設計

作成日: 2026-08-23 / 状態: **検討段階（パートナー未定・未着手）**
関連: `docs/business-model-diagram.md` / `docs/vehicle-passport-design.md` /
`docs/merchant-revenue-sharing-design.md` / `src/lib/vehicleReport/*`

## 1行結論

**市場に既にある「信用回復ローン／自社ローン」は、名前と中身が一致していない — 自社ローンの支払い実績は指定信用情報機関に登録されないので、完済しても信用情報は回復しない。**
だから Ledra が組むべき相手は「お金を出せる会社」ではなく **「指定信用情報機関の加盟会員である信販会社または貸金業者」** に限られる。
Ledra 側の役割は **① 担保（車）の状態証明 ② 契約後の担保モニタリング ③ 全国の実行ネットワーク** の3点に限定し、**Ledra は貸さない・保証しない**。この形なら Ledra に新たな業登録は要らず、既存の車両履歴レポート機能がほぼそのまま与信レポートになる。

**ただし前提が1つ欠けている。**本番の VIN 付き車両は現時点で **1台**（登録24台中）で、提携先に出せるデータ量に達していない。しかもその原因の一部は**バグ**だった（入力済み VIN 6台のうち5台が正規化列に反映されず、パスポートから引けなかった）。バグは本 PR で修正した（§7-1）。台数そのものは営業の問題として別途残る。

## 0. なぜこの文書があるか

代表より「Ledra と自動車ローンを組み合わせた信用回復ローンをパートナーと立ち上げたい」との方針。
パートナー・スキーム・法務がいずれも未確定な段階なので、**実装に入る前に「誰が何を担い、どの登録が要り、Ledra が何を持ち込めるのか」を先に固定する**ための設計文書。コードは1行も書いていない。

## 1. 前提の整理 — 市場でいう「自社ローン」「信用回復ローン」の実態

| 論点 | 実態 | 出典 |
| --- | --- | --- |
| 自社ローンの法的性格 | 金融機関を介さず**販売店が代金を分割で受け取る「割賦販売」**。金銭の貸付ではない | [カルモマガジン](https://car-mo.jp/mag/category/tips/usedcar/in-house-loan/) / [スリークロス滋賀](https://www.ss-shokai.jp/magazine/own-loan-law/) |
| 金利 | 貸金業者でない販売店は利息を取れないため、**金利0%を掲げ、車両価格・手数料に上乗せして回収**するのが通例 | 同上 |
| **支払い実績の信用情報登録** | **登録されない。**販売店は信用情報機関の加盟会員ではないため、完済しても CIC / JICC のスコアは直接は改善しない | [カーマッチ](https://car-match.jp/shopblog/posts23162/) / [ゲットマイカー](https://getmycar.jp/news/2026/06/27/) |
| 事故情報の登録期間 | CIC・JICC は最長5年、KSC（全銀協・官報情報）は最長7年（2022年11月に10年→7年へ短縮） | [JICC](https://www.jicc.co.jp/aboutus/credit-info/registration) / [アルビノ](https://www.albino.co.jp/credit-information-expiry-period/) |
| 利用者の不満 | 総支払額の不透明さ、GPS 装着と遅延時の遠隔引き揚げ、保証範囲の争い | [自動運転ラボ](https://jidounten-lab.com/ownloan-terrible) |
| 市場 | 「信用回復ローン」「自社ローン」は既に比較記事が成立する程度に事業者が存在する（大手は成約3万件超・通過率95%超を掲げる） | [自動運転ラボ](https://jidounten-lab.com/creditrepair_loan_recommend) |

**ここから読み取れる勝ち筋は「審査を緩くすること」ではない。**通過率で戦う市場は既に飽和していて、しかも顧客が本当に欲しい「信用が戻る」という結果を誰も提供できていない。
Ledra が持ち込むべきは、**Ledra のプロダクト全体の主張とまったく同じもの — 透明性と証明**である。

## 2. 「信用回復」を名乗れるのは、貸し手が加盟会員のときだけ

組成主体（＝債権者になる人）の選択肢は3つしかない。ここが設計の分岐点。

| 案 | 組成主体 | Ledra 側に必要な業登録 | 支払い実績が信用情報に載るか | Ledra の役割 |
| --- | --- | --- | --- | --- |
| **A（推奨）** | 提携する**信販会社**（個別信用購入あっせん） | **不要** | **載る** | 与信データ提供・担保証明・送客 |
| **B** | 提携する**貸金業者**（オートローン） | **不要** | **載る** | 同上 |
| **C** | Ledra / 加盟店自身の**自社割賦** | 不要（ただし割賦販売法の行為規制は受ける） | **載らない** | 貸倒れリスクを自社で全負担 |

- 許可・登録が要るのは「前払式割賦販売業・前払式特定取引業（許可）」と「包括／個別信用購入あっせん業・クレジットカード番号等取扱契約締結事業（登録）」であり、**後払いの自社割賦そのものには登録制度が置かれていない**（[経済産業省 割賦販売法（後払分野）の概要・FAQ](https://www.meti.go.jp/policy/economy/consumer/credit/kappuhanbaihoatobaraibunyanogaiyofaq.html)）。
  → **推定**: 案C は業登録なしで成立しうる。ただし条文の直接確認ができていない（政府ドメインが本環境から取得不可）ため、**着手前に弁護士確認が必須**。
- **案C を選ぶなら「信用回復」を商品名・広告に使ってはいけない。**信用情報に載らないのに「信用が回復する」と表示すれば景品表示法上の優良誤認に当たりうる。既存事業者が事実上そこを踏んでいる領域であり、Ledra が同じ土俵に降りる理由はない。

**→ 採るべきは A（信販会社との提携）。**「信用回復」という言葉を、業界で初めて事実にできる。

### 2-1. ただし「回復」の意味を正確に握っておく

加盟会員が組成すれば支払い実績は信用情報に登録される。**しかしそれで既存の事故情報（異動情報）が消えるわけではない。**
事故情報は登録期間の満了で落ちる（CIC・JICC 最長5年、KSC 最長7年）のであって、良い支払い実績が上書きするのではない。

つまりこの商品が提供できるのは「**事故情報が消えたときに、そこに良好な取引実績が積み上がっている状態**」であって、
「今すぐ信用情報がきれいになる」ではない。**この2つを混同した表示をすると、案Aを採っていても景表法上の優良誤認になりうる。**
訴求は「払った実績が、次のローンの材料として残る」に留め、「ブラックが消える」に踏み込まない。§5-3 と合わせて文言は法務確認にかける。

## 3. Ledra が持ち込む非対称な資産 — パートナーが自前で作れないもの

信販会社が自動車ローンで負っているリスクは PD（延滞確率）と LGD（回収不足）の2つ。
**Ledra が触れるのは主に LGD 側で、しかも既に実装済みの資産で触れる。**

### 3-1. 担保（車）の状態証明 — 実装済み

`/v/[vin]` の有料車両履歴レポート（`src/lib/vehicleReport/`）は、複数の加盟店をまたいだ1台の施工・整備履歴を、
段階式スコープ（全履歴／直近Nヶ月）付き・購入時点でスナップショットされた形で開示する仕組みが**既に本番にある**。
履歴は Polygon アンカリング + RFC3161 タイムスタンプで改ざん検知が効き、写真は撮影 nonce・GPS 整合・C2PA まで通っている。

中古車査定の実務でも記録簿の有無は相場形成の材料として扱われている（[中古車売買バイブル](https://car-sokuhou.com/media/car-sale-warranty/)）が、
**その記録簿は「あるか無いか」しか分からず、真正性の保証がない。**Ledra のレポートは「本当にその整備が行われたこと」を証明する。ここが差。

→ 貸し手にとっての意味: **担保評価の精度が上がり、想定回収額のブレが縮む。**

### 3-2. 契約後の担保モニタリング — 副産物として得られる

自動車ローンは契約後、担保である車が今どうなっているか誰も分からない。
Ledra は加盟店網に車が入庫するたびに記録が増えるので、**「整備が継続されているか」という担保の健全性シグナルが自然に立つ**。
GPS で位置を追う既存手法（利用者から最も嫌われている部分）とは違い、**車の位置ではなく車の状態を見る**モニタリングになる。

### 3-3. 全国の実行ネットワーク

代表が47都道府県で出張作業をしてきた経緯と加盟店網により、**回収・現況確認・整備・再販を実際に動かせる**。
信販会社が最も持っていないのはこの実行部隊。LGD を机上でなく実際に下げられる。

### 3-4. 支払い行動の代替データ — 有望だが法務の壁が最も高い

`invoices`（`status`: draft/sent/paid/overdue/cancelled、`due_date`、`customer_id`）から
「整備代金を期日どおり払ってきたか」が原理的には出せる。信用情報に傷があっても実際の支払い行動は良好、という層を拾える。
**ただしこれは §5-1 の目的外利用・第三者提供の問題に正面からぶつかる。Phase 1 では使わない。**

## 4. 商品設計案 — 透明性で差別化する

商品名（仮）: **「証明付きオートローン」**。「信用回復ローン」は §2 の条件を満たしたうえで訴求文言としてのみ使う。

利用者への3つの約束:

1. **総額が最初に確定する** — 車両価格・手数料・保証料を分解して提示。既存自社ローンの最大の不満点。
2. **車の状態が証明されている** — 契約時に Ledra の改ざん検知付き履歴レポートを利用者にも同時開示（貸し手だけが見る、にしない）。
3. **払った実績が信用情報に載る** — 加盟会員である提携先が組成するので、完済が実際に次のローンへつながる。

3 は既存プレイヤーが構造的に真似できない（販売店は加盟会員になれない）。**ここが商品の堀。**

## 5. 着手前に潰す壁（この順で）

### 5-1. 個人情報保護法 ／ 信用分野ガイドライン ★最優先

- 加盟店が Ledra に預けている顧客情報は「施工・請求のため」に取得したもので、**与信判断のための第三者提供は当初の利用目的の外**にある可能性が高い。利用目的の変更または個別同意の取得が要る。
- 与信を扱う事業者には個人情報保護委員会の[信用分野における個人情報保護に関するガイドライン](https://www.ppc.go.jp/personalinfo/legal/shinyou_GL/)が別途かかる。
- **設計上の逃げ道**: **車両（VIN）の情報と個人の情報を分ける。**§3-1 の車両履歴レポートは車の情報であって、申込者本人が同意して提示する形にすれば、Ledra から貸し手への個人データ提供を発生させずに始められる（＝ Phase 0 が成立する理由）。
- 個人データを使う §3-4 は、同意設計が固まるまで着手しない。

### 5-2. 貸金業法・割賦販売法の「媒介」ライン

Ledra が申込書を預かる・条件を説明する・審査結果を伝える等に踏み込むと**貸付の媒介**に当たり、Ledra 側にも登録が必要になりうる。
**Phase 1 では Ledra は「レポートを売る／リンクを置く」以上のことをしない。**この線引きは弁護士に明文で引いてもらう。

### 5-3. 景品表示法

「信用回復」「審査通過率◯%」の表示は裏付け資料が要る。§2 の A/B を採らない限り「信用回復」は使わない。

### 5-4. 保証・GPS の扱い

GPS 装着を要件にするか。利用者の不満の中心であり、Ledra の「透明性」ブランドと真っ向から衝突する。
**推奨は非装着**。§3-2 の状態モニタリングで代替できるかを PoC で測る。

## 6. 最小の立ち上げ — 新機能をつくらずに始める

### Phase 0: 与信レポートを既存機能のまま提携先に使ってもらう（**新規コード0行**）

提携先の審査担当が `/v/[vin]` で対象車両のレポートを購入して見る。それだけ。
- Ledra 側の作業: 契約と、レポート価格の法人向け設定のみ。
- ここで測るもの: **提携先の審査担当が「このレポートで担保評価が変わる」と言うか。**言わなければこの事業は成立しない。**最初に殺すべき仮説はここ。**
- 副次効果: レポート売上は既存の `vehicle_report_revenue_shares` で加盟店に自動還元される。**「技術が、資産になる。」がローン領域でもそのまま効く。**

### Phase 1: 法人向け API（Phase 0 が通ってから）

既存の外部 v1 テナント API に VIN 指定のレポート取得を1本足す。審査システムへの組み込み用。
既存のレポート生成・スコープ・課金・還元をそのまま呼ぶので、**新規の課金基盤も台帳も要らない**。

### Phase 2: 送客導線

加盟店・顧客ポータルから提携先の申込ページへリンク。§5-2 の線引き確定が前提。

### Phase 3（将来・別判断）: 支払い実績の代替データ提供

§3-4。同意設計が固まるまで着手しない。

## 7. 実データで測ったカバレッジ — **この事業の前提は現時点で成立していない**

§9 のアクション1（VIN カバレッジ計測）を本番 DB に対して先に実行した。結果:

| 指標 | 実数（2026-08-23 時点・本番） |
| --- | --- |
| 登録車両 | **24台** |
| うち車体番号（`vin_code`）が入力済み | **6台** |
| うち車両パスポート／レポートから引ける（`vin_code_normalized`） | **1台** |
| 施工証明書 | 44件（18台に紐づく） |
| 車両履歴レポートの購入実績 | **0件** |
| 加盟テナント | 22 |

**確実（本番DBへのクエリ2経路で確認済み）。**

読み方は2つある。

1. **母数がそもそも小さい。**24台では、提携先がどの申込車両を持ってきてもヒットしない。Phase 1 以降（API 提供・審査組み込み）は**現時点では成立しない**。
2. **しかも入力済みの VIN の 6分の5 が機能に届いていなかった** — これはバグだった。次項。

### 7-1. 発見したバグ: 入力された VIN がパスポートに反映されていなかった（修正済み）

マイグレーション `20260424000004` が `vehicles.vin_code_normalized` を追加して**一度だけ**バックフィルしたが、**その後この列を埋める仕組みがどこにも無かった**。
アプリ側の書き込み経路（車両作成 `/api/vehicles/create`、CSV インポート、車検証 OCR からの作成、パスポート upsert、管理画面の新規・編集フォーム）はいずれも `vin_code` しか書いておらず、DB トリガーも無い。

結果として、**バックフィル以降に入力された VIN はすべて `vin_code_normalized` が NULL のまま**になり、`/v/[vin]`・有料レポート・加盟店還元のいずれからも引けない状態だった。本番の内訳がそれを裏付けている。

| 車両の作成時期 | 台数 | `vin_code_normalized` |
| --- | --- | --- |
| 2026-04-07（バックフィル前） | 1 | あり |
| 2026-05-08 〜 2026-08-21（バックフィル後） | 5 | **すべて NULL** |

**修正**: `supabase/migrations/20260823000000_vehicles_vin_normalized_trigger.sql` を追加した。
書き込み経路が5箇所以上（今後モバイル・外部 v1 API も増える）あるため、呼び出し元ごとに直すのではなく **DB トリガー1本**に寄せている。既存の `set_updated_at` と同じパターン。
併せて、元のバックフィルに無かった **NFKC 正規化を追加**した。

さらにコードレビューで、**照合する側も壊れていた**ことが分かった。`/v/[vin]`（`getPassportData.ts`）は URL の VIN を
`trim().toUpperCase()` するだけで、ハイフンも全角も処理していなかった。保存側が正規化されても、
`/v/JH4-DC5-3001` のような URL では自分の車両を引けない。共通ヘルパー `normalizeVin()` は既にあり、
v1 API とレポート購入では使われていたのに、この1箇所だけが独自実装だった。ここも `normalizeVin()` に寄せた。
（生の入力を正規化しているのはこの1箇所だけで、他の `trim().toUpperCase()` は正規化済みの値に対する防御的な呼び出しだった。）
マイグレーションには自己検証（トリガーが実際に正規化するか／保存値がルールと食い違う車両が残っていないか）を同梱し、
壊れたら CI で落ちるようにした。ローカルの PostgreSQL 16 で、修正前の本番状態を再現して適用・再適用・異常系まで確認し、
正規化ルールが JS 側の `normalizeVin()` と全10ケースで一致することも突き合わせ済み。

**既知の副作用（意図的）**: VIN を編集すると正規化キーが変わるため、`vehicle_report_orders`（購入済みレポートのアクセス権）と
`vehicle_passports`（アンカリング済み）が旧キーに取り残される。カスケードは本 PR の範囲外とし OPEN_QUESTIONS に起票した。
正規化列を古いまま放置するほうが害が大きい（持っていない VIN で引けてしまう）ため、この形を採っている。
現時点でレポート購入実績は0件なので実害は無い。

### 7-2. 経済性の枠（数字は【要確認】のまま）

- 提携先の年間オートローン組成件数: 【要確認】
- レポート単価（法人向け）: 現行の一般向け既定は ¥3,000（`DEFAULT_REPORT_PRICE_JPY`）。法人価格は未定
- 加盟店還元率: 既定 70%（`merchant_share_bps`。この値自体が【要確認】のまま）

**先に必要なのは価格ではなく台数。**Phase 0（提携先1社に見せて反応を測る）は24台でも実行できるが、Phase 1 以降に進む条件は「Ledra 上の VIN 付き車両が提携先の申込と実用的に交差する台数に達すること」。その台数の定義自体がまだ無い（OPEN_QUESTIONS 起票）。

## 8. パートナー選定基準（この順に効く）

1. **指定信用情報機関（CIC / JICC）の加盟会員であること** — これを満たさない相手は候補ですらない（§2）
2. 自動車ローン、特に**信用情報に傷のある層への与信経験**があること
3. **担保評価に外部データを入れる余地があること** — 審査が完全に固定ロジックの相手だと Ledra のレポートが刺さらない
4. 全国の販売網に依存せず、Ledra の加盟店網と補完関係にあること

# 追補（2026-08-24）— 単独展開する場合、Ledra を使う／使わないで何が変わるか

代表より「単独で信用回復ローンを展開するにあたり、通常よりも差別化するために Ledra を活用した場合と
そうでない場合を比較したい」との依頼。本編（§2）は提携モデル前提なので、単独モデルを別に整理する。

## 11. 先に前提の訂正 — 「単独」には2形態あり、名乗れる商品名が違う

Ledra を使うかどうかとは**別の話**として、単独展開では次の分岐が先に来る。

| | C-1 自社割賦（登録なし） | C-2 貸金業登録を取得 |
| --- | --- | --- |
| 必要な登録 | なし（後払いの割賦販売そのものには登録制度が置かれていない・**推定**） | 貸金業登録 |
| 指定信用情報機関への加盟 | **不可** | **加入が義務** |
| 支払い実績の登録 | されない | **義務**（遅滞なく提供） |
| 「信用回復」を名乗れるか | **名乗れない** | 名乗れる |
| 収益 | 車両価格・手数料への上乗せのみ（利息は取れない） | 金利を取れる |

JICC の加盟資格は「**貸金業法または割賦販売法に基づく登録事業者**であること」とされている
（[JICCへの加盟](https://www.jicc.co.jp/aboutus/member-entry)）。自社割賦は登録事業者ではないので、
**C-1 では制度上どうやっても信用情報に載せられない。**
逆に C-2 なら、個人向け貸付を行う貸金業者は指定信用情報機関への加入と個人信用情報の提供が
**法令上の義務**なので（[日本貸金業協会](https://www.j-fsa.or.jp/association/money_lending/law/designated_credit.php)）、
「払った実績が信用情報に載る」は自動的に実現する。ここは営業努力ではなく制度で決まる。

### C-2 の壁（Ledra では1つも解けない）

- 純資産 5,000万円以上（貸金業を営む間ずっと下回らないこと）
- 常勤の貸金業務取扱主任者の設置
- **常務に従事する役員のうち、貸付けの業務に3年以上従事した経験を有する者がいること**
  （出典: [サポート行政書士法人](https://www.shigyo.co.jp/search_post/kinyu/money-lending/about/) /
  [アクシア行政書士事務所](https://www.axia-office.co.jp/works/188/)。**要弁護士・行政書士確認**）

3つ目は現在の HOLY の体制には無い。**貸付経験3年以上の人材を常務役員として迎えるのが C-2 の実質的な入口。**
資金（融資原資）も別途要る。**Ledra はこのどれにも寄与しない。**

## 12. だから比較すべきは「名乗れるか」ではなく「経済性と商品の質」

**Ledra は信用回復ローンを名乗る資格を与えない。**それは §11 の登録の話。
Ledra が変えるのは「いくら貸せるか」「焦げ付いたときいくら戻るか」「誰に売れるか」の3つ。

### 12-1. ライフサイクル別の比較

| 局面 | Ledra なし（通常の自社ローン／信用回復ローン） | Ledra あり |
| --- | --- | --- |
| 集客 | 広告・ポータル依存。競合と同じ土俵で「通過率」を訴求 | 加盟店網からの送客。整備の相談から入るので与信前に接点がある |
| 車両の仕入れ | 業者オークション。状態は出品票のみ | 同上＋加盟店経由。**納車前整備を自社/加盟店で行い記録を残せる** |
| 審査（PD＝延滞確率） | 本人属性と信用情報。**ここは Ledra でも変わらない** | 同左。**車のデータは人の返済能力を語らない** |
| 融資額の決定（EAD） | 車両価格に対して勘で掛け目を置く | 状態が分かるので実勢価値に対して掛け目を置ける。**過大融資を避けられる** |
| 契約時の説明 | 車の状態は口頭説明。総額の内訳が不透明という業界不信をそのまま背負う | 施工前後写真＋改ざん検知付きの履歴を顧客にも同時開示。総額の内訳も分解提示 |
| 期中のモニタリング | GPS で位置を追う（利用者の不満が最も集中する部分） | 点検・整備の入庫記録で**車の状態**を見る。位置ではないので摩擦が小さい |
| 延滞の予兆 | 入金遅延が起きてから気づく | 定期整備の途絶が資金繰り悪化の先行指標になりうる（**仮説・未検証**） |
| 引き揚げ時 | 業者に委託。車の状態が引き渡し時と違うと言われても反証できない | 47都道府県の出張ネットワークで現況確認。**引き渡し時の状態が証明済みなので争いにならない** |
| 再販（回収） | オークションに卸す＝卸値 | 整備して自社/加盟店網で**小売で売り切れる** |
| 完済後 | 顧客の手元に「ただの古い車」が残る | **履歴が証明された車**が残る。次の乗り換えの下取りで効き、再来店につながる |

### 12-2. 回収率が上がる理由を正確に言う（ここを間違えると効果を過大評価する）

**「整備履歴があるから査定が上がる」ではない。**査定実務での記録簿等の加点は1万円程度とされており
（[中古車売買バイブル](https://car-sokuhou.com/media/car-sale-warranty/)）、**この経路の効果は誤差**である。

効くのは別の経路。**引き揚げた車を、自社/加盟店網で整備して小売で売り切れること。**
オークションに卸すのと小売で売るのとでは回収額が変わる。Ledra はここで、
① 整備が実際に行われたことを買い手に証明して不安を下げ、② 全国の実行部隊を束ねる、という補助をする。
**主役はネットワークで、Ledra は摩擦を下げる装置。**この順序を逆にすると効果を見誤る。

### 12-3. 効果の枠（**以下の数値はすべて仮置き。実績値ではない**）

構造を見るための試算。実データが無いので、入力値はすべて仮の数字。

- 融資額 100万円/件、貸倒率（件数ベース）15%
- Ledra なし: 貸倒時の回収率 40% → LGD 60% → 期待損失 = 15% × 60% = **9.0%**
- Ledra あり: 回収率 55%（整備＋小売再販で +15pt と仮定）→ LGD 45% → 期待損失 = 15% × 45% = **6.75%**
- 差 = **2.25ポイント = 1件あたり 22,500円**、100件（融資残高1億円）で **225万円**
- さらに EAD の精度向上で貸倒率が 15%→13% になれば 13% × 45% = 5.85% → 差 **3.15ポイント**

**感応度の結論: 効き幅が最も大きいのは回収率（LGD）であって、審査精度ではない。**
Ledra を入れるなら、審査アルゴリズムに凝るより**引き揚げ〜整備〜小売再販の導線を作るほうが先**。

## 13. 単独モデルが Ledra と相性が良い決定的な理由 — カバレッジ問題が消える

提携モデル（本編 §7）の最大の障害は、**提携先が持ち込む車が Ledra に無いこと**だった。
本番実測で VIN 付き車両は1台（登録24台中）で、Phase 1 以降が成立しない。

**単独なら、扱う車を自分で決められる。**融資対象車を全部 Ledra に登録し、納車前整備の記録を残せば、
**カバレッジは初日から100%。**さらに契約条件として自社/加盟店での点検を組み込めば、期中の記録も途切れない。
提携モデルではどちらも強制できない。

**この一点で、Ledra 活用の前提条件は単独モデルのほうが揃っている。**
本編 §2 の「採るべきは A（提携）」は、「信用回復を名乗るには加盟会員でなければならない」という理由からで、
その理由は C-2（自ら貸金業登録を取る）でも同じく満たせる。**A と C-2 は排他ではなく、壁の種類が違う。**

| | A: 加盟会員と組む | C-2: 自ら貸金業登録 |
| --- | --- | --- |
| 壁 | 提携先が見つかるか／Ledra のデータ量 | 純資産5,000万・主任者・**貸付3年経験の役員**・融資原資 |
| 着手までの速さ | 速い（Phase 0 は新規コード0行） | 遅い（登録に数か月〜。人材採用が先） |
| Ledra の価値 | データを売るだけ＝薄い | **12-1 の全局面で効く＝厚い** |
| 取れる収益 | レポート販売＋送客手数料 | 金利・手数料の全部 |
| カバレッジ問題 | **残る（現状の致命傷）** | **消える** |

## 14. Ledra を入れても解けないこと（正直に）

- **融資原資**。1円も助けない。単独展開の最大の壁はここ。
- **登録要件**（純資産・主任者・貸付3年経験の役員）。§11 のとおり。
- **PD（本人の返済能力と返済意思）**。Ledra のデータは車の話であって人の話ではない。
  ここを Ledra で改善できると説明したら、それは誇張になる。
- **クロステナントの厚み**。Ledra の車両履歴の本来の価値は「他店の履歴も含めて1台を追える」ことだが、
  単独モデルの初期は自社が作った履歴しかない。**効いているのはネットワーク効果ではなく、
  改ざん検知付きで記録が残ること**そのもの。ここを混同すると、資料で説明できない主張になる。
- **顧客への説明責任**。整備入庫の記録を与信・モニタリングに使うなら、利用目的にその旨を明記して
  同意を取る必要がある（自社顧客なので第三者提供の問題は消えるが、目的外利用の問題は残る）。
  「整備に来ないと督促される」と受け取られない設計が要る。

## 15. この追補からの示唆

1. **「信用回復」を名乗りたいなら、登録（A か C-2）が先。Ledra は後。**順序を逆にすると商品が成立しない。
2. **Ledra の効き所は回収（LGD）に集中している。**審査精度ではない。
   投資するなら引き揚げ〜整備〜小売再販の導線。
3. **単独（C-2）を選ぶなら、Ledra のカバレッジ問題は自動的に解ける。**
   これは提携モデルには無い利点で、本編の結論を単純な「A 一択」から
   「A は速い／C-2 は厚い、壁の種類が違う」に更新する。
4. **C-2 の実質的な入口は資金でも登録手続きでもなく、貸付経験3年以上の常務役員の確保。**
   ここが埋まらない限り C-2 は検討に留まる。
5. 12-3 の試算に使った数値はすべて仮置き。**実際の判断には自社の貸倒率と回収率の見込みが要る**が、
   これは事業を始めるまで得られない。まず A で小さく回してデータを取り、C-2 に進むかを決める、
   という順序が安全（OPEN_QUESTIONS 起票）。
