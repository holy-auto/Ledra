# ADR-0004: 訂正は上書きではなく版の追加

- Status: Accepted(2026-08-19, IMP-001)

## 背景

v2.0 §12.3: VERIFIED 済み証明書 v1 に誤りが判明した場合、v1 を SUPERSEDED として
残し、v2 を再検証して Current VERIFIED にする。旧 QR からは「新しい版があります」と
最新版へ誘導する。現状は `certificate_edit_histories`(フィールド単位の差分追記)と
`certificate_versions`(内容ハッシュの Phase 1)まで実装済みで、版遷移
(SUPERSEDED / 再検証 / 旧版からの誘導)は未実装
(`docs/implementation/requirement-trace.md` §1.4)。

## 決定

1. 顧客承認額・証明書内容・証跡に裏づけられた重要フィールドの訂正は、
   **in-place 上書きではなく Correction Record / 新版の追加**で表現する。
2. 訂正は「訂正リクエスト → 承認 → 訂正レコード」の経路を通す(v2.0 §12.3、
   実装は IMP-030)。承認前の訂正は効力を持たない。
3. 版ポインタ(Current)は再検証完了後にのみ切り替える。旧版は SUPERSEDED として
   照会可能なまま残し、404 にしない。
4. 重大問題は REVOKED を使い、「無効化された事実」を第三者が確認できる形で公開する
   (v2.0 §12.4)。

## 影響

- 顧客・保険会社・第三者から見た履歴の一貫性が守られる(「いつの間にか数字が変わった」を
  構造的に不可能にする)。
- IMP-030(訂正ワークフロー)・IMP-043(帳票の版管理)は本 ADR を前提に設計する。
