# ADR-0005: Certificate Gate はバックエンド単一判定

- Status: Accepted(2026-08-19, IMP-001)

## 背景

v2.0 §19.4: 正式証明の発行可否は10条件(ワークフロー完了 / 必須証跡あり / 必須証跡
同期済み / 部品整合性 / 店舗内レビュー / 顧客確認が現行版 / Payment Policy 充足 /
未処理訂正なし / 未解決 Integrity Alert なし / 必要承認完了)をすべて満たしたときのみ
READY とし、**バックエンド共通 Gate を唯一の判定源**とする。フロントエンド独自判定は禁止。
現状は写真必須ゲート(`src/lib/certificates/photoRequirement.ts`、サーバ側3箇所)と
サインオフ状態機械(`src/lib/signoff/state.ts`)に条件が分散しており、単一の Gate
評価器は存在しない(`docs/implementation/requirement-trace.md` §2 の §19 行)。

## 決定

1. 発行準備状態(READY 相当)の判定ロジックは、**サーバ側の単一評価器に集約する**
   (実装は IMP-028。既存の photoRequirement / signoff の判定はその評価器の
   入力条件として統合し、書き捨てない)。
2. UI は Gate の判定結果(不足条件の列挙を含む)を**表示するだけ**とし、
   UI 側で発行可否を再計算・上書きしない。
3. フロントエンドから VERIFIED(相当)状態を直接作る API 経路を設けない。
   状態遷移は冪等なバックエンド処理(ジョブ/イベント)経由でのみ起きる。
4. Gate 条件の緩和・バイパスに相当する変更は、実装判断ではなくプロダクト判断であり、
   代表の明示的な承認なしに行わない。

## 影響

- 「なぜ発行できないか」が常に具体的な不足条件として説明可能になる(v2.0 §12 受入条件)。
- 後続タスクは新しい発行条件を追加するとき、UI ではなく Gate 評価器に追加する。
