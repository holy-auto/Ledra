# ADR-0003: 証跡は不変・追記のみ

- Status: Accepted(2026-08-19, IMP-001)

## 背景

v2.0 は「原本証跡は不変/追記のみ。訂正・差し替えはリンクで残し、黙って上書きしない」
を製品不変条件とする(§7.1, ガイド §1)。現状の実装は部品装着側に DB トリガの
完全凍結ガード(`supabase/migrations/20260603000001_part_installations_guard.sql`)が
あるが、証明書写真(`certificate_images`)は DB 行の削除が可能で、完全な追記専用では
ない(ハッシュ+アンカーによる改ざん検知方式。`docs/implementation/current-architecture.md` §7)。

## 決定

1. 証跡(写真・音声・部品照合・確認記録)の**原本オブジェクトとメタデータは
   削除・改変しない**ことを実装原則とする。撮り直し・差し替えは新しい証跡を追記し、
   旧証跡を invalidated / replacement としてチェーンに残す(v2.0 §8.2)。
2. ハッシュ対象の原本バイト列を後加工しない(マスキングは公開レンディション側で行う。
   v2.0 §18.3)。
3. 既存の `certificate_images` 削除経路の扱い(追記専用への移行、または削除を
   invalidation に置換)は、証跡ワークフローを実装する **IMP-023 / IMP-030 で解消する**。
   それまでの間、新規コードは証跡の物理削除・上書き保存を追加しない。
4. 監査ログ(`audit_logs` / `vehicle_histories` 等)は通常のアプリ API から
   編集可能にしない。

## 影響

- 「間違えたので消す」は API 設計として不可。invalidate + 追記で表現する。
- ストレージコストは増えるが、証明可能性(このプロダクトの価値の根幹)を優先する。
