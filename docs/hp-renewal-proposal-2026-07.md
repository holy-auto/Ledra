# Ledra HP リニューアル改善提案書（2026-07）

> 依頼: 「最先端な企業のイメージ」への刷新 + 要望①〜⑩の反映。
> 前提: 現行 HP（`src/app/(marketing)`）のフルコード監査に基づく提案。ゼロから作り直す提案ではなく、**既にある資産を最大限活かして最短距離で世界水準に引き上げる**構成。

## 0. 現状評価 — 何が既にあり、何が足りないか

### 既にある強み（壊さないこと）

| 資産 | 場所 | 評価 |
| --- | --- | --- |
| ダークテーマのデザインシステム（Apple Blue + Gold、Type ramp 7段、Serif=格式限定ルール） | `DESIGN_SYSTEM.md` / `globals.css` | 一貫性は上場 SaaS 水準。触らず拡張する |
| SEO 基盤（sitemap.ts / robots.ts / JSON-LD Organization・WebSite・FAQ・Pricing / canonical / OG 画像） | `src/app/sitemap.ts` ほか | 骨格は完成。不足は「スキーマの種類」と「コンテンツ量」 |
| CTA 計測（PostHog + GA4、`trackLocation` 付き CTAButton） | `CTATracker.tsx` | A/B テストの土台が既にある |
| ターゲット別 LP（施工店/保険会社/代理店/BtoB）+ 機能詳細 15 ページ | `for-*` / `features/*` | 情報設計は既に「大手 SaaS」型 |
| 透明性コンテンツ（GrowthJourney / financial-transparency / data-disclosure / MediaAwardsRow の Coming soon 正直表示） | 各ページ | 要望⑧の思想が既に実装されている。**ここが他社に真似できない差別化軸** |
| Remotion（動画レンダリング基盤）、実スクショ 10 枚 | `remotion/` / `public/marketing/screenshots` | モーション資産の材料が揃っている |

### 足りないもの（本提案の対象）

1. **記憶に残る「シグネチャー・モーション」が無い** — 現状はぼかしブロブ + タイプライター + ScrollReveal。丁寧だが、Stripe / Linear / Vercel 級の「このサイトと言えばアレ」が無い。
2. **プロダクトを"触れる"体験が無い** — スクショは静止画。SaaS の購買決定はプロダクト UI を見た瞬間に大きく動く。
3. **正直さが「点」で、ブランドの「幹」になっていない** — 透明性ページは存在するが、トップの物語に編み込まれていない。
4. **大手向け PoC 導線が非公開ページ 1 枚だけ**（しかも矛盾あり、後述）。
5. **SEO はコンテンツ量とスキーマ網羅で伸びしろが大きい**。

## 1. 【要望①】モーション/3D — 「動く」ではなく「語る」モーションへ

### 設計原則（最重要）

3D・モーションは**要望⑦（離脱率低減）・④（SEO/Core Web Vitals）と正面衝突する**要望。世界の最先端サイト（Stripe, Linear, Igloo, Vercel）が実際にやっているのは「全画面 3D」ではなく、**軽量な 1 つのシグネチャー演出 + 全体は上質なマイクロモーション**。以下の予算で設計する:

- LCP < 2.5s / INP < 200ms を**モーションより優先**（モバイル実測で担保）
- 3D は **1 箇所だけ**、遅延ロード + 静止画ポスターのフォールバック必須
- `prefers-reduced-motion` 完全対応（アクセシビリティ = 要望⑨の高齢者対応とも直結）

### 提案A: シグネチャー 3D「浮かぶ証明書」（Hero）

- **内容**: ヒーロー右側の現行スクショ枠を、**実物の施工証明書がガラス質の 3D カードとして浮遊・微回転し、スクロールで「ブロックチェーンに刻まれる」演出**（カードがハッシュ化 → チェーンのブロックに格納されるまでをスクロール連動で見せる）に置き換え。プロダクトの本質（改ざん不可能な証明）を 5 秒で伝える。
- **技術**: `three` + `@react-three/fiber` + `@react-three/drei`（新規依存はこの 3 つのみ）。`next/dynamic` で遅延ロード、初回描画は現行スクショを静止ポスターとして表示 → WebGL 準備完了後にクロスフェード。モバイル低スペック機は `navigator.hardwareConcurrency` / `deviceMemory` で判定し静止画のまま。
- **代替案（より軽量）**: Rive（state machine 付きベクターアニメ、実行時 ~50KB）で同じ演出を 2.5D で。3D の質感を諦める代わりに CWV リスクほぼゼロ。**PoC 商談で「技術力」を見せたいなら A、離脱率を最優先するなら Rive**。

### 提案B: スクロールテリング「1台の車の一生」セクション（トップ中腹）

- 1台の車が「施工 → 証明書発行 → 保険査定 → 中古車売買」と流れる横スクロール連動ストーリー。各ステップで実際の画面モックが差し替わる。
- **技術**: CSS Scroll-Driven Animations（`animation-timeline: view()`）を第一候補に。JS 不要・メインスレッド負荷ゼロ・Safari も 26 で対応済み。非対応ブラウザは静的な縦積みに自然にフォールバック。**新規依存ゼロで実装可能**。

### 提案C: マイクロモーションの底上げ（全ページ）

- 数値は既存 `AnimatedCounter` を全 KPI 表示に統一適用
- カード hover に微細な 3D tilt（CSS `perspective` のみ、ライブラリ不要）
- セクション見出しに既存 `ScrollReveal` の variant を追加（clip-path reveal）
- ページ遷移に View Transitions API（Next.js 対応済み、1 行設定）

### 提案D: Remotion 資産の活用

- 既存の `remotion/` で 30 秒のプロダクトツアー動画をレンダリングし、Hero の「デモを見る」を**その場でモーダル再生**に（遷移離脱を防ぐ = 要望⑦）。YouTube 埋め込みではなく自前 mp4 + `preload="none"` で軽量に。

## 2. 【要望②】SaaS としての解説 — 機能・想い・メリデメ・実画面

### 2-1. インタラクティブ・プロダクトツアー（最重要施策）

静止スクショを**クリックで進む疑似操作デモ**に置き換える。「証明書を発行してみる」を訪問者自身が 4 クリックで体験できる（実データ不要のモック UI。既存 `HeroDashboardMock` の発展形で、外部 SaaS 不要・自前実装可能）。トップ・/features・/demo に埋め込み。

### 2-2. 「想い」= 創業ストーリーページ `/story`

- 代表の実経歴（専門学校中退 → 町工場で整備・鈑金塗装 → 47都道府県出張 → 法人化）は**それ自体が「現場のリアル」の証明**であり、要望⑧のブランドと完全に一致する。飾らず時系列で。
- 業界の信頼低下・大手不正問題への問題意識 → 「履歴に嘘をつかせない」というプロダクト思想への接続を 1 本のナラティブに。
- 構成: 年表（スクロール連動）+ 現場写真 + 「なぜ Ledra なのか」。E-E-A-T（経験・専門性・権威性・信頼性）の観点で SEO にも直接効く（要望④）。

### 2-3. メリット・デメリットの正直開示 `/honest-comparison`（要望⑧と統合)

- 「Ledra に向いていない方」を先に書く（例: 紙運用を変える気がない/発行月◯件未満なら無料枠で十分、など)。
- 競合・代替手段（紙 + Excel、汎用 CRM）との正直な比較表。自社が負ける項目も載せる。
- **これをやる SaaS は日本にほぼ無い。信頼で売るプロダクトの LP として最強の differentiator であり、「〇〇 比較」系の検索クエリも取れる**（要望④）。

### 2-4. 実画面（モックアップ）

- 既存スクショ 10 枚を `ScreenshotLightboxImage`（既存）でギャラリー化した `/product-tour` を新設し、機能ページ 15 枚すべてから相互リンク。
- スクショは `scripts/capture-screenshots.ts`（既存）で CI 定期再生成し、**常に最新の実画面**を掲示 = 要望⑧。

## 3. 【要望③】CTA 構成 — 問い合わせの角度を上げる

現状: Hero に 3 本（無料で試す/資料DL/デモ）+ 最終 CTABanner。良い骨格だが「全員に同じ 3 本」なのが弱点。

### 提案

1. **温度別 CTA の 3 段設計**（全ページ共通ルール化）
   - 低温: 「資料 3 点セットをダウンロード」（メールのみで完了、フォーム 1 項目）
   - 中温: 「デモを触ってみる」（登録不要のインタラクティブツアーへ → 2-1）
   - 高温: 「無料で始める」/（企業向けページでは）「PoC の相談をする」
2. **スクロール連動スティッキー CTA**（モバイル）: ファーストビュー通過後に画面下部へ薄いバーで出現。閉じるボタン付き・一度閉じたら session 中は再表示しない（鬱陶しさは離脱要因 = ⑦）。
3. **ページ文脈で CTA を変える**: `/for-insurers` は「デモを依頼」、`/roi` は「この試算結果を資料で受け取る」、`/cases` は「同業の事例を相談する」。既存 `trackLocation` があるので**効果測定はそのまま乗る**。
4. **フォームの摩擦削減**: `/contact` を「メール + 用件 1 択」の 2 項目に短縮し、詳細は返信後にヒアリング。フォーム項目数は問い合わせ率に直結する。
5. **PostHog で A/B テスト運用開始**: CTA 文言（「無料で試す」vs「5分で証明書を発行してみる」）から着手。計測基盤は導入済みなので実験フラグを立てるだけ。

## 4. 【要望④】SEO 徹底強化

### 即修正（バグ級）

- **`/poc` が sitemap に載っているのに `noindex`**（`sitemap.ts` と `poc/page.tsx` の矛盾）。しかも内容がトヨタ固有の商談資料であり、**要望⑤（秘匿）・⑥の観点でも公開 URL に置くべきでない**。→ sitemap から除外し、認証付き `/pitch` 系へ移動 or トークン付き URL 化。

### 構造強化

1. **JSON-LD の網羅**: 既存 Organization/WebSite/FAQ に加え、`SoftwareApplication`（価格・評価）、`BreadcrumbList`（全下層）、`Article`（blog/news）、`HowTo`（guide）、`Service`（features 各ページ）。既存 `JsonLd.tsx` にコンポーネント追加のみ。
2. **パンくずの UI 実装**（下層全ページ）: 構造化データと視覚ナビの一致。内部リンク網の強化にもなる。
3. **コンテンツクラスター戦略**（最大の伸びしろ）: ハブ「施工証明書とは」を柱に、「コーティング 証明書」「PPF 保証書 発行」「板金 履歴 管理」「中古車 施工履歴」等のスポーク記事を MDX（既存 blog 基盤）で月 4 本。用語集 `/glossary`（施工・保険・ブロックチェーン用語 50 語）をプログラマティックに生成し、全記事から内部リンク。
4. **タイトル/見出しの検索意図適合**: 現行トップ title「Ledra | WEB施工証明書SaaS」は良いが、H1「現場の技術を、業界の力へ。」は感情訴求のみ。**H1 はそのまま活かし、直下の説明文に主要クエリ（施工証明書・電子発行・改ざん防止）を確実に含める**（現状ほぼ OK、キーワード監査だけ実施）。
5. **技術面**: 全マーケページの ISR 化確認、`next/image` の `sizes` 監査、CWV を Lighthouse CI で PR ごとにガード（`check-bundle-size` が既にあるので隣に追加）。モーション施策①が SEO を壊さない保険。

## 7. 【要望⑦】離脱率低減

1. **速度 = 最大の離脱対策**: モーション予算（§1）+ Lighthouse CI ガード（§4-5）。
2. **ファーストビュー 5 秒テスト**: 「誰の・何を・どうする」が 5 秒で伝わるか。現行 Hero は概ね合格だが、サブコピーが抽象的（「業界全体に信頼と価値を」）。**タイプライター行の「施工記録を、改ざん不可能なデジタル証明書に。」の方が本質を突いており、こちらを主説明文に昇格**させる。
3. **トップの長さを 20% 圧縮**: 現在トップは 18 セクション。ご利用シーン（FeatureCard 3 枚）と WhatYouCanDo は内容が重複気味 → 統合。スクロール完走率を PostHog で見て、到達 10% 未満のセクションは下層へ移す。
4. **出口に次の一歩を必ず置く**: 記事末尾に関連記事 3 本 + 温度別 CTA(§3)。404 にも検索とトップ導線。
5. **exit-intent は使わない**（品位を落とし「正直ブランド」⑧と不整合）。代わりにスクロール 70% 到達時のスティッキー CTA(§3-2) で回収。

## 8. 【要望⑧】嘘のないリアル — これをブランドの幹にする

既存の GrowthJourney / financial-transparency / Coming soon 表記は業界唯一級の資産。**「点」から「幹」へ**:

1. **トップに「すべて実数」セクション**: 発行済み証明書数・加盟店数・アンカリング済みブロック数を**本番 DB から直接カウントして表示**（キャッシュ 1h）。数字が小さくても出す。「この数字は本番データベースの実数です。私たちは履歴に嘘をつかせないサービスです — まず自分たちから。」の 1 文を添える。**小さい数字を隠さないことが最大のコピーになる**。
2. 導入事例 0 件時の「最初の 1 社を募集しています」表示（既存 CustomerCasesSection の思想）を全ページで統一。
3. `/honest-comparison`（§2-3）と `/story`（§2-2）でメッセージを補強。
4. 編集ルール明文化: 「実在しない導入企業ロゴ・盛った数値・ストック写真の『お客様の声』を使わない」。

## 9. 【要望⑨】迷わない登録導線 — 中学生にも祖父母にも

現行 signup は 1 ページ・インライン検証・マジックリンク対応で既に良質。仕上げる:

1. **入力は段階分割**: Step1 メールだけ → Step2 店舗名（あと 1 問）→ 完了。パスワードはマジックリンクを既定にして**そもそも入力させない**（既存 magic モードを default に昇格するだけ）。
2. **登録前に「登録の流れ」3 コマ漫画的図解**を signup 上部に（①メール入力 → ②届いたリンクをタップ → ③店名を入れて完了。所要 2 分）。
3. **高齢者対応**: フォーム文字 16px 以上・タップ領域 44px 以上・専門用語ゼロ（「テナント」「マジックリンク」→「お店のページ」「ログイン用リンク」）・エラーは赤字だけでなく文章で解決策を書く（既存実装ほぼ準拠、文言監査のみ）。
4. **電話サポート導線**: signup 画面に「うまくいかない時は LINE / 電話で一緒に登録します」を明記。現場業界では最強の安心材料で、要望③の問い合わせ増にも直結。
5. 全 CTA の行き先を `/signup` に統一し、途中遷移（pricing 経由の迷子）を PostHog ファネルで監視。

### 技術方針まとめ

- 新規依存は最小限: P3 の `three`/`@react-three/fiber`/`@react-three/drei`（または Rive ランタイム 1 つ）のみ。P0〜P2 は**既存スタック（CSS Scroll-Driven Animations / Remotion / 既存コンポーネント）で完結**。
- すべてのモーションは `prefers-reduced-motion` 対応 + 静的フォールバック必須。
- 「正直さ」はコピーの方針ではなく**編集ルールとして明文化**し、全ページに適用する。
