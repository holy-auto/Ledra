## 候補（CLAUDE.md の代表者経歴・問題意識から）

## 「撮り忘れ」をゼロにする ― 現場を止めない写真ガイドの作り方

- 切り口: 整備・施工の現場で起きる「必要な写真の撮り忘れ」を、長いフォームや強制停止で
  解決しようとすると現場に嫌われる。Ledraは工程ごとに「撮る写真・確認する項目」を
  ベテランが宣言し、作業者にはガイドとして提示・タップで確認、未確認でも一度警告するだけで
  必ず進める設計にした。「強制停止は最小限」という思想を、実装レベル（サーバ側ハードゲートを
  あえて採らずUI側ソフト警告にした判断）まで落として説明できる。
- 想定読者: 整備・鈑金・コーティング店の経営者/現場責任者、業務システムを作る開発者。
- 状態: 未着手
- メモ: DECISION_LOG.md 2026-07-17 エントリ（強制ゲートを捨ててソフト警告にした理由・
  過去の「進行不能バグ」回避）が一次材料。特定テナントの数値・個人情報は含めない。

  代表・堀越友輔のキャリアパス。
- 想定読者: 整備・鈑金・コーティング業界の経営者、起業に関心がある同業者。
- 状態: 未着手
- メモ: CLAUDE.md の代表者情報が一次ソース。具体的なエピソードは別途取材が必要
  （現時点では確度の高い詳細情報なし）。

## なぜ「証明書 × 改ざん検知」を作ったのか

  代表が「証拠を残せる仕組み」としてLedraを作った経緯。
- 想定読者: エンドユーザー（車両オーナー）、整備店オーナー。
- 状態: 未着手
- メモ: README.md の「施工証明書 × 改ざん検知」の思想（Polygonアンカリング +
  施工前後写真ゲート）と接続できる。

## 「現場に記録作業を増やさない」ソフトの作り方

- 切り口: 職人が普段どおり作業するだけで、必要な記録・証明・共有が自然に残る——
  写真は撮るだけ・メモは話すだけ・不足は後からAIが検出、という現場負担ゼロ設計の思想。
  点検フォームを音声/カメラ直行/Storage写真に格上げした改善（＝機能を足すのではなく
  入力の手間を消す）を具体例に。
- 想定読者: 整備・鈑金・コーティング業界の経営者、現場DXに関心のある同業者。
- 状態: 未着手
- メモ: `docs/field-workflow-roadmap.md`（現場負担軽減ロードマップ）と
  `docs/feature-audit-brushup-2026-07.md` の提案1が一次ソース。
  機密になりうる機能構成の粒度は出さず、「思想」に抽象化して書く（公開区分: 公開可の範囲で）。

## 「使われる機能」だけ残す — SaaSの機能別利用率を運営が毎月見る話
- 切り口: 多機能SaaSほど「作ったが使われない機能」が溜まる。Ledraでは運営が
  店舗ごとの機能別利用率（予約/作業記録/請求/証明書/顧客/決済を当月使った店舗の割合）を
  毎月確認する仕組みを入れた。数字で「機能の生死」を判断する運用の話。
- 想定読者: SaaS/プロダクト開発者、同業の経営者。
- 状態: 未着手
- メモ: ログイン「回数」は追跡テーブルが無く実測できなかったため、last_sign_in_at
  ベースの「アクティブ会員」で近似した、という設計上の割り切り（捏造せず既存データで
  honest に近似する）もエピソードとして使える。数字・店舗名など内部指標は転記しない。
