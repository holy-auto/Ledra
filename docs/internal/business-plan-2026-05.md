## エグゼクティブサマリ

**Ledra は、自動車施工（コーティング・PPF・板金・整備）の事実をデジタル証明書として発行・流通させるマルチテナント SaaS です。**

国内 5.5 兆円の自動車整備市場は、施工記録が紙・LINE・Excel に分散し、保険会社・中古車流通は「いつ・誰が・どんな施工をしたか」を後から検証できない構造的欠陥を抱えています。Ledra は、施工店向け業務 SaaS（予約 → 作業 → 証明書発行 → 請求を 1 画面で完結）を入口に、発行された証明書を顧客・保険会社・中古車市場が共通参照できる "車の施工台帳" に育てます。

**プロダクトはすでに本番稼働中**です。4 ポータル（施工店 / 代理店 / 保険会社 / 顧客）+ モバイルアプリ（iOS/Android）、160+ DB マイグレーション、400+ API、2,000+ テストケース。Polygon アンカリングによる証明書改ざん検知、Stripe / Square / Apple Tap to Pay 連携、車検証 OCR（Anthropic）も実装済み。

事業フェーズは **「広く薄く」を「狭く深く」に塗り直すフェーズ**。Lighthouse 保険会社（標的: 損保ジャパン、2026-05-13 決定）1 社の本番接続と、Woven by Toyota Partner Program への PoC 提案を 2 本柱に、**24 ヶ月で ARR 10 億円**（店舗 ¥6 億 + 保険 ¥3 億 + 流通/OEM ¥1 億）を狙います。

## 1. Why Now — なぜ今やるのか

### 1.1 マクロトレンド: 車のメンテ履歴がデジタル化される 10 年に 1 度の局面

3 つの潮流が同時に立ち上がっており、施工履歴のデジタル化を後押ししています。

| 潮流 | 状況 | Ledra への追い風 |
|---|---|---|
| **SDV (Software Defined Vehicle) 化** | トヨタ・日産・ホンダが車両 OS / OTA 開発加速 | 整備履歴のデジタル参照が標準前提に |
| **車検 / OBD 検査の電子化** | 2024 年から OBD 検査開始、車検制度のデジタル連携拡大 | 紙の施工記録は法令上も非効率に |
| **損保業界の不正請求対策強化** | 2024 年のビッグモーター問題以降、損保各社が施工エビデンス検証を強化 | 第三者検証可能な証明書の需要が立ち上がり |
| **中古車流通の透明性ニーズ** | UCDA 等が査定基準のデジタル化を推進 | 施工履歴 = 査定の付加情報 |

### 1.2 競合状況: 国内に「業務 SaaS + 証明書 + 流通レイヤ」を統合した事業者は存在しない

国内競合分析（`docs/competitor-analysis-2026-05.md`）より：

- **米国先行プレイヤー**: Tekmetric（ARR $15M / 3,000 店）、Shopmonkey（ARR $29.7M / 6,000 店）はいずれも「整備店業務 SaaS」のみで、証明書ネットワークや保険連携は持たない
- **国内競合**: 紙 + Excel が大半、デジタル化されていても店舗ごとの自前 PDF 発行で、業界横断の検証ネットワークは未成立
- **施工証明書専業**: 既存サービスは PDF 発行のみで、改ざん検知・流通連携・業務管理を統合した事業者は確認されない

**Ledra の独自ポジション**: 業務 SaaS（店舗 DX） × 証明書ネットワーク（保険・中古車流通）の **二重ネットワーク効果** を狙える構造。

### 1.3 タイミングの優位性

> *"プロダクトはすでにある。次の 24 ヶ月は流通ネットワーク拡張のフェーズ。"*

- 2024〜2025 年で施工店業務 SaaS の機能セット（4 ポータル + モバイル）を完成
- 2026 年 H1 で監査スコア 7.4/10 まで品質を引き上げ、エンタープライズ調達対応の基盤整備（`docs/enterprise-readiness.md`）
- 2026 年 H2 〜 2027 年で Lighthouse 保険会社（損保ジャパン）の本番接続 + Woven by Toyota PoC を仕込む順序

## 2. プロダクト — 何を作っているか

### 2.1 1 行サマリ

> **業務 SaaS と証明書ネットワークが地続きの 1 プロダクト。** 施工店の業務管理が、そのまま業界全体の施工台帳になる。

### 2.2 4 ポータル + モバイル

| ポータル | 利用者 | 主要機能 |
|---|---|---|
| **Admin** (`/admin/*`) | 施工店オーナー / スタッフ | 案件ワークスペース（予約 → 来店 → 作業 → 証明書発行 → 請求 → 入金）、顧客台帳、車両台帳、Stripe Connect 課金、Square / Apple Tap to Pay 連携、POS、Storefront、Academy、レポート、監査ログ |
| **Agent** (`/agent/*`) | 代理店パートナー | 施工店紹介、コミッション管理、商談ステータス、ランキング |
| **Insurer** (`/insurer/*`) | 損保会社 | 証明書検索（VIN / 顧客 / 期間）、案件レビュー、SLA トラッキング、不正請求検知用ダッシュボード |
| **Customer** (`/c/[id]`, `/my/*`) | 一般車両オーナー | 証明書閲覧 / 共有、車両 / 施工履歴、追加施工予約、保険提携店検索 |
| **Mobile** (iOS / Android) | 施工店スタッフ + 顧客 | 現場での写真撮影 + 証明書発行 + Tap to Pay 決済 |

### 2.3 施工証明書の差別化（Polygon アンカリング）

```
施工写真撮影
   ↓
証明書発行 (Admin)
   ↓
写真ハッシュ計算 (SHA-256)
   ↓
Polygon にアンカリング
   ↓
QR / 公開URL (/c/[public_id]) で第三者検証可能
   ↓
顧客 / 保険会社 / 中古車市場が横断参照
```

- **改ざん検知**: 写真の 1 ビット変更でハッシュ不一致 → 自動アラート
- **公開検証**: 認証不要で URL/QR から証明書を確認できる（保険会社の社内システムから直リンク可能）
- **将来拡張**: C2PA メタデータ、NFC タグ連携、Vehicle Passport（`/v/[vin]` ページ実装予定）

## 3. 課題 — なぜ Ledra が必要か

### 3.1 施工店の業務分散

**現場の実態**: 真面目に施工する事業者ほど書類で消耗する。

- 施工記録（紙台帳・写真）、顧客情報（Excel）、車両情報（LINE）、保険会社向けエビデンス（メール添付）が **4〜5 つのツールに分散**
- 1 件あたりの書類対応時間: 15〜25 分（複数店舗運営の場合さらに二重入力）
- 月間の工数ロス: 中規模店（月 200 件施工）で **40〜80 時間**

### 3.2 保険会社・中古車流通の検証不能

**業界の実態**: 施工した事実が後から検証できない。

- 損保会社が「コーティング施工した」と申告された車両を後追い検証する手段がない
- 中古車査定は施工履歴を加味せず、コーティング・PPF の付加価値が査定に反映されない
- 結果: 不正請求の温床、優良施工店の差別化が困難、消費者の情報非対称

### 3.3 Ledra の解決アプローチ

```
①  施工店の業務統合 (ペインキラー)
   → 案件ワークスペースで予約から入金まで 1 画面完結
   → Free プランから入れる導入障壁の低さ

②  証明書のデジタル化 + 改ざん検知 (差別化)
   → Polygon アンカリング = 後から改ざんできない証拠
   → QR / URL で誰でも検証可能

③  業界横断ネットワーク (ロックイン + 拡張)
   → 保険会社・中古車事業者が参照する側に立つ
   → 施工店は "参照されたい" 動機で Ledra に集まる
```

→ **ペインキラー → 差別化 → ネットワーク効果** の 3 段ロケット構造。
