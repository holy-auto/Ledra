## 3. 業界課題① 施工店の業務分散

- **目的**: 課題の深さを「数字」で見せる
- **要素**:
  - 現場写真 (紙の施工記録 / LINE スクショ / Excel 台帳) を 3 枚並べる
  - 数字: 1 件あたりの書類対応時間 / 月間の工数ロス / 二重入力の発生回数
  - キーフレーズ: "真面目に施工する事業者ほど書類で消耗する"

---

## 4. 業界課題② 保険・中古車流通の検証不能

- **目的**: 流通レイヤの空白を提示
- **要素**:
  - フロー図: 施工店 → 保険会社 / 中古車市場 の情報非対称
  - 数字: 不正コーティング請求の推定額 / 中古車査定ブレ率
  - キーフレーズ: "施工した事実が後から検証できない"

## 5. Why Now

- **目的**: 今やる必然性を示す
- **要素**:
  - SDV (Software Defined Vehicle) 化と整備履歴デジタル化の潮流
  - 車検制度 / OBD 検査の電子化スケジュール
  - 損保業界の不正請求対策強化
  - 中古車流通の透明性ニーズ (UCDA 等)
  - キーフレーズ: "車の履歴がデジタル化される 10 年に 1 度のタイミング"

## 6. プロダクト概観

- **目的**: "何を作っているか" を 1 枚で
- **要素**:
  - 4 ポータル図 (Admin / Agent / Insurer / Customer) + モバイル
  - `/admin/jobs/[id]` 案件ワークスペースのスクショ
  - 主要数字: 400+ API / 130+ migrations / 2,000+ tests
  - キーフレーズ: "業務 SaaS と証明書ネットワークが地続きの 1 プロダクト"

---

## 7. 施工証明書の差別化

- **目的**: 模倣困難性を技術で示す
- **要素**:
  - QR / 公開 URL `/c/[public_id]` のスクショ
  - Polygon アンカリングのフロー図 (写真 SHA-256 → on-chain)
  - C2PA / NFC タグ連携
  - キーフレーズ: "発行して終わり、ではなく検証され続ける証明書"

## 補足: HAKOBUNE (栗島さん) 向け差分修正

> 兄弟資料: `docs/internal/hakobune-inquiry.md` (HAKOBUNE 向け問い合わせ
> パッケージの本体)。HAKOBUNE は **シード特化・ハンズオン伴走型** で、
> 判断軸は **Founder-Market Fit と "今やる必然性"**。標準版は ALL STAR SAAS
> 想定の汎用構成なので、HAKOBUNE 向けには **Founder の一次情報** と
> **シード ラウンドの "深さ"** を前面に出す差分を入れる。

### 全体トーン

- 標準版の "業務 SaaS + 証明書ネットワーク + 流通レイヤ" の3層構造は維持
- ただし **Founder のオペレーター性** を全スライドの隅で繰り返し想起させる
  (写真・一人称表現・週次内製ループの図)
- "金額" よりも **"1社目近くの伴走関係性"** を希望する構成に
- ステージは **シード (プレシリーズ A 視野)** に絞る (Theta Times のように
  シリーズ A まで広く広げない)

### スライド単位の差分

#### #1 表紙

- 標準: Tagline「車の施工を、デジタルで証明する。」+ サブコピー「施工店 SaaS × 施工証明書ネットワーク」
- **差分**: サブコピーに **"施工現場のオペレーターが運営する垂直 SaaS"** を
  1 行追加。背景に detailing_holy の施工写真を薄く重ねる (Founder 由来を
  最初のスライドから示唆)。

#### #2 チーム

- 標準: 堀越 (CEO) の顔写真 + 施工現場写真 + PM/Eng/Sales
- **差分**:
  - **堀越のオペレーター背景を最厚化**。detailing_holy のロゴ + 店舗写真 +
    施工後の車両写真を 3 枚並べる
  - **週次内製ループ図** (現場ヒアリング → 機能仕様 → リリース → 現場
    フィードバック) をスライド下部に追加
  - キーメッセージ: **"施工現場で稼ぐ Founder が、業界の痛点を週次で機能化
    している"**

#### #3 業界課題① 施工店の業務分散

- 標準: 紙/LINE/Excel 写真 3 枚 + 工数の数字
- **差分**: 数字を **Founder 一人称** に書き換える。例:
  - 「私が detailing_holy で月◯時間を書類対応に取られている」
  - 「保険会社からの過去施工問い合わせに、写真を探し出すのに平均◯分」
  - 「顧客の◯%が自分の車に何が施工されたか覚えていない」
  → "資料の数字" ではなく "Founder の現場一次情報" として読ませる

#### #4 業界課題② 保険・中古車流通の検証不能

- 標準: フロー図 + 不正請求推定額 + 査定ブレ率
- **差分**: detailing_holy が実際に受けた **「保険会社からの過去施工確認
  問い合わせ」** の実例 (匿名化) を 1 枚追加。"自分の店で起きていること"
  として課題を提示

#### #5 Why Now

- 標準: SDV / 車検電子化 / 損保不正対策強化 / 中古車透明化
- **差分**: **+ Polygon (L2) ガス代低下による on-chain アンカリングの
  実用化** を 5 点目として追加。技術側の必然性も含めて "今" を多角的に
  握らせる

#### #6 プロダクト概観

- 標準: 4 ポータル図 + `/admin/jobs/[id]` スクショ + 400+ API / 130+ migrations
- **差分**: 中核メッセージを **"本番稼働済 = 仮説検証ではなく "伸ばす"
  フェーズ"** に。シード VC が最も嫌う "デモは綺麗だが本番が動かない" の
  否定を明示

#### #7 施工証明書の差別化

- 標準のまま。QR / 公開 URL / Polygon アンカリング / C2PA / NFC

#### #8 デモ動画 / スクリーンショット

- 標準のまま。5 分動画ダイジェスト + スマホ証明書 + 保険会社検索

#### #9 ビジネスモデル

- 標準: プラン別 ARPU + アドオン + 中長期トランザクション
- **差分**: 3 階建ての各層に **`docs/ledra-goals-strategy-2026-05.md` ベース
  の根拠** を明示:
  - 店舗 ARR ¥6 億 = 1,400 店 × ¥35,000/月 (Tekmetric 比較で半分)
  - 保険 ARR ¥3 億 = 3〜5 社 × ¥500 万〜¥1,000 万/月
  - 流通 ARR ¥1 億 = OEM/中古車のトランザクション
  → 18-24 ヶ月で ARR 10 億 (シードからの逆算で過大に見えないようにする)

#### #10 市場規模 (TAM/SAM/SOM)

- 標準: TAM 5.5 兆円 + SAM + SOM
- **差分**: **ミクロ算定**を 1 行追加。「整備全体 9 万社 × ARPU ¥35,000 =
  約 380 億」 → SOM を "リアルに取れる範囲" として小さめに見せる方が
  シード VC には誠実に映る (過大評価感の打消し)

#### #11 GTM 戦略

- 標準: 直販 + 代理店 + 流通プル の 3 段
- **差分**: 流通プルの中で **"損保ジャパン Lighthouse 1 社集中"** を最上位
  レイヤに格上げ。`docs/ledra-goals-strategy-2026-05.md` の "PoC 並走の罠
  回避" を明示し、HAKOBUNE が好む "1 社に深く" の姿勢と接続させる

#### #12 トラクション

- 標準: 店舗数推移 + MRR + 主要パイロット + 顧客の声
- **差分**: パイプラインを **3 つの確度別** に分けて明示:
  - **本番接続 (¥◯/月)**: `<最新値>`
  - **Lighthouse 候補**: 損保ジャパン (PnP Japan Insurtech 経由で接点獲得中)
  - **PoC 仮説構築中**: Woven by Toyota / 中古車流通 X 社
  → "PoC 5 社並走で 0 件契約" の罠を踏まないことを暗に示す

#### #13 競合マップ

- 標準: 縦軸 業務 SaaS↔ネットワーク / 横軸 自前 PDF↔デジタル証明書
- **差分**: **3 軸目に "オペレーター発か否か"** を点の大きさ / 色で追加。
  Ledra のみが "オペレーター発 + 業務 + 証明書 + 流通" の全条件を満たす
  立ち位置を可視化

#### #14 ロードマップ

- 標準: 6 / 12 / 24 ヶ月のマイルストーン
- **差分**: 6 ヶ月目に **"損保ジャパン 本番接続 OR 撤退判断"** を明示。
  シード VC が嫌う "PoC を惰性で続ける" の否定を示す。撤退条件を持っている
  Founder は判断力で信用される

#### #15 調達希望と使途

- 標準: ラウンド / 金額 / 使途 / 12ヶ月後 KPI
- **差分**:
  - ラウンドを **シード (プレシリーズ A 視野)** に明示限定
  - 想定構成を **"HAKOBUNE リード想定 / フォロワー <未定>"** まで踏み込む
    (栗島さんに "リード前提で当てに来た" 印象を残す)
  - 使途は **損保営業 (Lighthouse 集中) / 施工店 GTM / 初期コア採用** の
    3 点に絞る (Theta Times 版より範囲を狭める)
  - 締めに **"HAKOBUNE / 栗島さんに期待する伴走領域"** を 3 行で明示
    (`hakobune-inquiry.md` §4-4 から流用)
