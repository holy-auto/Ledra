## ❓ 質疑・即答 3 秒（深掘り対策）

- **請求書だけ？実務の帳票は？** → **インボイス対応の帳票8種（見積/納品/発注/発注請/検収/領収/請求/合算請求）を1画面**。案件データから請求・見積はAIが下書き→確定で自動送付（決済リンク同梱）。**金額確定は必ず人**。証明書屋ではなく**見積〜入金まで回る業務SaaSが土台**
- **AIで誤入力事故は？** → 3-way（auto/suggest/manual）+ confidence閾値で自動降格 + **"壁3"（金額・本人確認・発行は自動化しない）**
- **改ざん不能の根拠は？** → チェーンに載せるのは**ハッシュだけ**。写真はAIが偽造を弾く / 内容はSHA-256→Polygonで書換検知 / `/c/[public_id]`で第三者検証
- **部品装着インテグリティとは？物理シール？** → No。物理印は必ず破られると認めた上で、**"複数の関門を全部欺けない"状態**を作る（抑止+検知+説明責任）。装着→AI検査→**納品書OCR三方照合(証明書/請求=仕入納品書=実物)**→**三重署名(顧客の電話OTP所持証明+事業者署名+RFC3161 TSA)**→アンカー→**納車時に顧客自身がLINE確認**。決め手＝店が支配できない出口で第三者(顧客)が検証。`src/lib/parts`・Phase1-8実装済/本番DB適用済（Polygon/TSA/SMSはenv有効化）
- **【必ず来る】発行する瞬間に偽の写真で偽装できるのでは？** → 改ざんは2種。**①発行後の書換＝チェーンで不可能**／**②発行時の偽装＝信頼の連鎖で潰す**：撮影時(C2PA署名/端末認証)→アップロード時(**サーバ側ハッシュ**＋EXIF/ディープフェイク検査)→発行時(**写真なしは発行不可**＋グレード刻印)→発行後(チェーン固定)。締め＝「保険会社は**premiumグレードだけ受理**と運用で締められる。紙に後から判子の世界とは別次元」。正直ライン＝C2PA署名は段階展開中、今効いてるのはサーバ側ハッシュ+EXIF+写真必須+ディープフェイク
- **大手が作れるのでは？** → 業務+改ざん不能証明書+AIを**両側のデータが溜まるまで作れない**後発の壁
- **損保ジャパンは？** → 正直に「**標的決定済・接点獲得フェーズ**」。1社本番化でテンプレ化→2社目以降3-6ヶ月
- **機能広すぎでは？** → 中古車/BtoB等は**アドオン化（凍結）決議済**。証明書+保険連携が主役
