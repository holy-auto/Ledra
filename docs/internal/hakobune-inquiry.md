```
Ledra は、自動車のコーティング・PPF・板金・整備など「車に施工した事実」を
デジタル証明書として発行・流通させるマルチテナント SaaS です。対象は国内
約5.5兆円規模・数万事業者の自動車整備/カーケア領域 — 紙とExcelとLINEで
回り続けてきた典型的なレガシー産業です。

施工店の現場では、施工記録・顧客情報・車両情報・保険会社向けの確認情報が

一方で保険会社や中古車流通の現場では「いつ・誰が・どんな施工をしたか」を
後から検証する手段が乏しく、不正請求や品質トラブルの温床になっています。

Ledra は施工店向けの業務 SaaS (予約 → 来店 → 作業 → 証明書発行 → 請求 →
入金を1画面に統合した案件ワークスペース) を入口に、発行された施工証明書を
顧客・保険会社・中古車市場が共通参照できる "車の施工台帳" に育てています。
証明書は QR / URL で公開検証でき、写真ハッシュは Polygon にアンカリング
することで第三者改ざん検知を実現しています。

施工店 (Admin) / 代理店 (Agent) / 保険会社 (Insurer) / 顧客 (Customer) の
4ポータル + モバイルアプリ (iOS / Android) を提供し、レガシー産業に分散した
価値の流れを1つのプラットフォームへ集約することを目指しています。
```

## 4. ★ ストーリーライン — オペレーター・ファウンダー × レガシー履歴インフラ (本資料の核)

HAKOBUNE はシード特化・ハンズオン伴走型。判断の中心は **Founder-Market
Fit と "今やる必然性"**。Ledra は **(a) 施工現場を自ら回すオペレーターが、
(b) 紙・Excel・LINE で回り続けた5.5兆円産業の "履歴" を、(c) SDV/法令
転換期の今、業界横断で取りに行く** という3点で必然性を語る。

### 4-1. テーゼ接続の1段論法 (面談冒頭で握らせる順序)

```
1. 私 (堀越) は自動車ディテイリング店 detailing_holy を運営する
   オペレーター。施工現場で日々「証明書が紙で残らない」課題を肌で持つ
   — Founder-Market Fit がドメイン由来で構造的に成立
2. 対象は国内約5.5兆円・数万事業者の自動車整備/カーケア。紙・Excel・
   LINE で回り続けたレガシー垂直産業の典型
3. Ledra は単なる店舗 SaaS ではなく、施工の「履歴」を業界横断で検証可能に
   する "履歴レイヤ" (証明書ネットワーク)
4. 履歴レイヤは保険会社・中古車流通・OEM が参照する → 上流からの逆引きで
   施工店が Ledra を採用する二重ネットワーク効果
5. SDV化・損保不正請求対策強化・中古車透明化要請の同時進行で、"車の履歴
   がデジタル化される10年に1度のタイミング" がまさに今 = Why Now
```

### 4-2. なぜ我々が勝てるか (Founder の一次情報 + 既存資産)

HAKOBUNE が最も重視する Founder-Market Fit に正面で答える。

```
(a) 施工現場のオペレーター出身
    detailing_holy を自ら運営し、紙・LINE・Excel の現場痛点を一次情報で
    保有。"施工後に証明書がどこにも残らない" "保険会社からの問い合わせに
    過去の写真を探し出せない" "顧客が自分の車に何が施されたか思い出せない"
    といった具体痛点を日次で観察 → 機能仕様に直結できる体制

(b) プロダクトはすでに動く ("作る" ではなく "伸ばす" フェーズ)
    本番稼働済 / 4ポータル + モバイル / 130+ DB マイグレーション /
    400+ API / 2,000+ テスト。仮説検証期を抜け、再現性のあるオンボーディング
    と GTM 設計に集中できる段階

(c) 業務 SaaS と証明書ネットワークが地続きの1プロダクト
    "業務管理" だけの SaaS や "証明書発行" だけのプロダクトは存在するが、
    両方を統合し、かつ流通レイヤ (保険・中古車・OEM) を持つ事業者は国内に
    存在しない認識。施工店の利用が増えるほど検証ネットワークの価値が
    上がる二重ネットワーク効果 = 模倣困難
```

- SDV (Software Defined Vehicle) 化と整備履歴デジタル化の制度的潮流
