## 0. 一行サマリ（結論）

Ledra の成長は「店舗数」ではなく、次の順で管理する。

**証明を作れる → 証明が選ばれる → 取引で使われる → 業界標準になる → 価格・審査を変える → 他業界へ展開する**

North Star は店舗数でも発行件数でもなく **検証済み意思決定イベント数（VDE: Verified Decision Events）** — 第三者が Ledra の履歴を確認して意思決定に使った回数。最終的な収益は `年間有料VDE × 平均課金単価` に収束する。

最終ポジション: **自動車の証明 SaaS ではなく、高価値資産の「仕事と履歴」を第三者が検証できる証拠インフラ。**

---

## 1. North Star Metric — VDE（検証済み意思決定イベント数）

店舗数・発行件数だけを追うと「使われない証明書」が増える。North Star は次にする。

**VDE = 第三者が Ledra の履歴を確認し、意思決定に利用した回数**（買取・仕入れ・販売・保険・保証・査定・監査など）

代表的な VDE イベント:

- 買取査定で履歴を確認した
- オークション出品審査に使われた
- 中古車の仕入れ判断に使われた
- 購入前確認に使われた
- 保険金支払審査に使われた
- 保証加入・保証修理の判断に使われた

なぜこの指標か（各指標が測るもの）:

| 指標 | 分かること |
|---|---|
| 店舗数 | Ledra を導入した事業者数 |
| 発行件数 | 記録が作られた量 |
| 閲覧数 | 記録への関心 |
| **VDE** | **実際に経済活動を動かした量** |
| **有料 VDE** | **Ledra の収益化された価値** |

トランザクション売上 = **年間 VDE × 平均課金単価**。

## 2. KPI ツリー

最上位: **年間有料 VDE**。その下に 6 つの指標群を置く。

| 指標群 | 主要 KPI |
|---|---|
| 供給 | 稼働店舗数、発行事業者数、月間発行件数 |
| 品質 | 証拠完成率、顧客確認率、再発行率、記録不備率 |
| 履歴密度 | 2 件以上の履歴を持つ車両数、平均履歴件数 |
| 第三者利用 | 第三者閲覧数、有料閲覧率、API 照会数 |
| 経済効果 | 査定時間削減、紛争削減、価格差、保険審査時間 |
| 収益 | 店舗 ARR、閲覧売上、API 売上、1 車両当たり売上 |

### 特に重要な中間指標

**車両履歴密度** = `2件以上の検証可能な履歴を持つ車両数 ÷ Ledra に登録された車両数`
1 件だけなら「証明書」。2 件・3 件と時系列で積み上がって初めて「車両履歴データベース」になる。

**第三者利用率** = `発行店舗以外の組織に閲覧された証明数 ÷ 発行された証明総数`
この数字が高いほど、Ledra は店舗ツールから業界インフラへ近づく。

## 3. 普及マイルストーン（Milestone 0〜5）

> 期間は目安。KPI はすべて **目標値（仮）**。

### Milestone 0 — 「証明を作れる」（現在〜6か月）

**目的:** 現場の負担を増やさず、証拠品質の高い記録を継続的に作れる状態にする。

**巻き込む人:** コーティング店 / 電装・用品取付店 / 鈑金塗装店 / 整備工場 / 店舗顧客 / 弁護士・法務専門家 / 証拠・データガバナンスの専門家

**始めること:**
- 証明に必要な必須項目の標準化 / 施工種類別テンプレート
- 写真・部品・作業者・顧客確認の入力設計 / 店舗ごとの入力方法を極力統一
- 顧客本人の閲覧は無料
- データ訂正・取消・異議申立てルールの策定 / すべてのイベントに一意 ID を付与

**浸透のさせ方:** 最初から「業界インフラ」「ブロックチェーン」を売らない。店舗には「クレームを防ぐ／顧客説明を楽にする／良い仕事を残す」という即時価値で導入してもらう。

**KPI 目標（仮）:**

| KPI | 目標 |
|---|---|
| 稼働店舗 | 30〜50 店舗 |
| 累計証明 | 3,000〜5,000 件 |
| 月間稼働率 | 70% 以上 |
| 証拠完成率 | 85% 以上 |
| 顧客確認率 | 70% 以上 |
| 発行時間中央値 | 3 分以内 |
| 3 か月継続率 | 85% 以上 |

**次段階への条件:** 導入店舗が「Ledra がなくても作業できるが、なくなると困る」と感じている。

### Milestone 1 — 「証明が選ばれる」（6〜18か月）

**目的:** Ledra の証明が、店舗の販売力・信頼性を高める状態を作る。

**巻き込む人:** 地域の有力施工店 / 複数店舗チェーン / 部品・用品メーカー / 部品卸 / コーティング剤メーカー / 消費者 / 自動車メディア / 業界インフルエンサー

**始めること:**
- 「Ledra 証明対応店」の表示 / 店舗検索ページ
- 証明付き施工商品のパッケージ化 / メーカーと認定施工記録の共同設計
- 消費者向け履歴ページ / 証明対応店の導入事例
- 証明がある車両とない車両の比較調査

**浸透のさせ方:** 証明を「追加作業」ではなく「証明付きの施工メニュー」として商品に内包する。顧客に「証明を付けますか」と選ばせるより、その店舗の標準サービスにする方が普及しやすい。

**KPI 目標（仮）:**

| KPI | 目標 |
|---|---|
| 稼働店舗 | 150〜300 店舗 |
| 累計証明 | 5 万〜10 万件 |
| 履歴 2 件以上の車両 | 1 万台以上 |
| 顧客閲覧率 | 50% 以上 |
| 年間店舗継続率 | 85% 以上 |
| メーカー・卸連携 | 3〜5 社 |
| 地域チェーン導入 | 3 社以上 |

**次段階への条件:** 消費者が「Ledra 証明がある店舗・商品」を選び始める。

### Milestone 2 — 「証明が取引で使われる」（18〜36か月）

**目的:** Ledra の履歴を、買取・仕入れ・小売・保険・保証の判断に利用してもらう。

**巻き込む人:** 中古車買取会社 / 中古車販売会社 / オートオークション / 車両保証会社 / 損害保険会社 / 損害調査会社 / リース・レンタカー / 査定会社 / 業務 SaaS・基幹システム会社

**始めること（利用目的別レポート）:** 買取査定 / 仕入れ判断 / オークション出品 / 小売説明 / 保証審査 / 保険修理確認。
同時に **API / 一括照会 / 法人アカウント / 請求書払い / 月間閲覧枠 / 1 件 550 円の単発閲覧** を整備。

**浸透のさせ方:** 「全車両で使って」ではなく、高額車・修復歴判断が難しい車・用品装着の多い車・輸入車・保証対象車・事故修理車から限定 PoC。

**KPI 目標（仮）:**

| KPI | 目標 |
|---|---|
| 稼働拠点 | 1,000〜3,000 拠点 |
| 累計証明 | 100 万件 |
| 法人 API 連携 | 3〜5 社 |
| 年間有料 VDE | 10 万件以上 |
| 取引への添付率 | 10% 以上 |
| 550 円閲覧売上 | 年間 5,500 万円以上 |
| 法人契約継続率 | 90% 以上 |
| 審査時間削減 | 20% 以上 |

**次段階への条件:** 店舗が発行するから使われるのではなく、**買取・保険・販売側が証明を要求し始める**。

### Milestone 3 — 「証明が業界標準になる」（3〜5年）

**目的:** Ledra のデータ形式・証明要件を、特定企業だけの仕様ではなく業界で使える標準にする。

**巻き込む人:** 国土交通省 / 経済産業省 / 金融庁 / 消費者庁 / 整備・鈑金業界団体 / 中古車・オークション業界団体 / 保険業界団体 / 消費者団体 / OEM・部品メーカー / 大学・研究機関 / 弁護士・監査法人

> `【要確認】` 行政は自動車部品サプライチェーンで企業間データ連携・トレーサビリティの実証を進め、電池パスポートのデータ管理システム／ガイドライン構築も進行中とされる。Ledra は部品製造側ではなく、装着・施工・整備後の現場データを補完する位置を狙える（外部制度動向は要検証）。

**始めること:** 車両施工履歴の共通データ項目 / API 仕様の公開 / データ移行・可搬性 / 発行者確認ルール / 証明取消・訂正ルール / 第三者監査制度 / 認証事業者制度 / 紛争処理ルール / 一般社団法人による中立運営 / Ledra 以外のシステムでも準拠可能な仕様。

**浸透のさせ方:** 「Ledra を業界標準にする」ではなく「**Ledra が提唱する証明仕様を業界標準にする**」。システムを独占するより、標準を広げ、その標準に最も適した基盤を Ledra が提供する方が普及する。

**KPI 目標（仮）:**

| KPI | 目標 |
|---|---|
| 稼働拠点 | 1 万拠点 |
| 累計証明 | 1,000 万件 |
| 年間有料 VDE | 100 万件 |
| 外部 API 連携 | 20 社以上 |
| 共通仕様採用システム | 3 サービス以上 |
| 業界団体との実証 | 5 件以上 |
| 第三者監査合格率 | 99% 以上 |
| データ欠損率 | 1% 未満 |

**次段階への条件:** Ledra 以外の企業・団体が、Ledra の証明要件を参照してサービスを作り始める。

## 4. ステークホルダーを巻き込む順番

行政・大企業から始めるより、次の順が現実的:

```
① 証拠を作る人      施工店・整備店
        ↓
② 証拠の恩恵を受ける人  顧客・車両所有者
        ↓
③ 証拠で判断する人    買取・販売・保険・保証
        ↓
④ 証拠を大量利用する    オークション・大手チェーン・SaaS
        ↓
⑤ ルールを作る人      業界団体・行政・消費者団体
        ↓
⑥ 証拠から価格を決める人  金融・保険・査定・AI
```

行政には構想段階で「認めてください」ではなく、**店舗データ・顧客の利用実績・紛争削減効果・保険審査の実証・業界横断 PoC** を持っていく方が強い。

## 5. 普及モデル（差別化 → 標準化）

```
① 差別化    Ledra 証明がある店舗は信頼できる
② 優遇     Ledra 履歴がある車両は査定・審査が早い
③ 取引条件   高額車・保証車両には検証可能な履歴を求める
④ 標準化    履歴がないこと自体がリスクになる
```

最初から義務化を狙うより、**「使うと得をする → 使わないと不利になる」** の順が最も浸透しやすい。

## 6. 他業態への横展開（共通エンジン）

Ledra の本質を自動車から切り離すと 7 要素になる:

```
資産を特定する → 誰が何をしたか記録する → 写真・部品・書類を紐付ける
→ 当事者が確認・署名する → 改ざんを検知する → 第三者が照会する
→ 履歴を価格・保証・審査に使う
```

つまり共通エンジンは **「高価値資産に対する作業・整備・修理の証拠パスポート」**。

### 候補市場（優先順位）

| 業態 | 適合度 | 制度追い風 | 参入難度 | 優先度 |
|---|---|---|---|---|
| 建設機械・産業機械 | 5 | 4 | 3 | **最優先** |
| ドローン | 5 | 5 | 3 | 高い |
| 蓄電池・太陽光・EV 充電設備 | 4 | 5 | 4 | 高い |
| 住宅リフォーム・建物修繕 | 4 | 3 | 3 | 中期 |
| 医療機器 | 4 | 5 | 5 | 長期 |
| 航空機・航空部品 | 5 | 5 | 5 | 長期 |

- **建設機械・産業機械:** レンタル重機の貸出前・返却後・修理履歴証明を最初の PoC に。自動車の買取・事故修理に近く転用しやすい。`【要確認】` 国交省の ICT 施工が本格運用・原則化に向かうとされる。
- **ドローン:** 産業ドローンの点検・修理・バッテリー交換証明。`【要確認】` 国交省が特定飛行の飛行日誌（飛行記録・日常点検・点検整備記録の様式）を求めるとされ、記録義務が明確。
- **蓄電池・太陽光・EV 充電設備:** 既存の電池パスポートと競合せず、「製造後に誰がどこにどう設置・保守したか」という現場施工レイヤーを担う。`【要確認】` 経産省が電池パスポートのデータ管理システム・トレーサビリティ・ガイドラインを実証中とされる。
- **住宅リフォーム・建物修繕:** 防水・外壁塗装・太陽光設置の施工証明。完成後に内部が見えなくなるため施工途中の証拠価値が高い。
- **医療機器・航空:** `【要確認】` 航空は電子整備記録への移行が進み、電子署名・記録完全性・セキュリティ・システム間移行が課題とされ、Ledra が自動車で解く問題と構造が近い。ただし認証・安全責任・法規制・監査・国際標準の障壁が高く初期展開には不向き。建設機械・ドローン・エネルギー設備で実績を作った後の長期市場。

### 進出判断基準（5 項目中 4 つ以上該当する業界だけに進出）

1. 資産単価が高い
2. 整備・施工・修理が繰り返される
3. 所有者・管理者が途中で変わる
4. 履歴が価格・保証・安全に影響する
5. 第三者が履歴を確認する必要がある

満たさない業界に広げると単なる電子証明書サービスになり、課金理由が弱くなる。

## 7.【最優先】まずクリアすべき 5 つの課題

マイルストーンを実現するうえで、**店舗数を増やす前に** 解く 5 点。

| 順位 | 課題 | 失敗した場合 |
|---|---|---|
| 1 | 証明基準の標準化 | データが比較できない |
| 2 | 現場負担の削減 | 店舗が使わない |
| 3 | 550 円の課金理由 | 閲覧売上が成立しない |
| 4 | 法務・訂正ルール | 大手が採用できない |
| 5 | 第三者有料利用 | 店舗 SaaS から進化できない |

### 優先 1 — 「証明」の最低基準を決める

店舗ごとに自由入力だと、写真枚数・作業粒度・部品記載・作業前後比較・顧客確認の有無がバラつき、買取・保険・オークションが共通基準で判断できない。

**共通必須項目:** 車両識別情報 / 証明 ID / 施工・整備日時 / 作業場所 / 作業事業者 / 作業担当者 / 作業前の状態 / 作業内容 / 使用部品・材料 / 作業後の状態 / 写真 / 顧客確認 / 事業者確定 / 記録確定日時 / 修正・取消履歴。
**業務別追加項目:** コーティング / 電装・用品取付 / 鈑金塗装 / 部品交換 / 車検・整備 / 保険修理 / 中古車商品化。

**クリア条件（仮）:** 必須項目入力率 95% 以上 / 証拠完成率 90% 以上 / 写真不足率 3% 未満 / 修正・再発行率 3% 未満 / 業務別テンプレート 5 種類以上。

> 証明書を増やす前に **比較可能な証拠データ** を増やすのが最優先。

### 優先 2 — 現場負担を 3 分以内にする

競争相手は他社 SaaS ではなく「**何も記録しないこと・LINE・紙・スマホの写真フォルダ**」。手が汚れている／作業中に PC を触れない／写真整理が面倒／再入力が面倒、という現場制約がある。

**始めること:** 車両情報の自動入力 / 前回情報の引継ぎ / 業務別テンプレート / 写真撮影順ガイド / 音声入力 / AI による作業内容生成 / 部品ラベルの画像読み取り / 顧客への確認通知自動送信 / QR・NFC による車両呼び出し / 入力途中の自動保存。

**クリア条件（仮）:** 発行時間中央値 3 分以内（目標 2 分）/ 月間稼働店舗率 70% 以上 / 30 日継続 80% 以上 / 3 か月継続 85% 以上 / 1 店舗当たり月間発行 20 件以上。

> 見るのは登録店舗数ではなく **月 1 件以上発行している稼働店舗数**。

### 優先 3 — 「550 円を払う対象」を明確にする

「履歴閲覧に 550 円」だけでは弱い（URL 共有・スクショ・再閲覧・所有者本人課金の問題）。550 円は **Web ページ閲覧料ではなく「取引・審査のための認証済みレポート取得料」** と再定義する。

**レポート例:** 買取査定 / 仕入れ判断 / オークション出品 / 小売説明 / 保証審査 / 保険修理確認。同じ車両でも利用目的が違えば別の意思決定イベント。

**推奨料金構造:**

| 利用者 | 料金 |
|---|---|
| 車両所有者本人 | 無料 |
| 施工・発行店舗 | 月額プラン内 |
| 一般第三者 | 550 円／認証レポート |
| 中古車事業者 | 従量 または 月間パック |
| 大手法人 | 基本料 + API 従量 |
| 保険・保証会社 | 月額 + 審査件数課金 |

**クリア条件（仮）:** 有料利用企業 3 社以上 / 有料レポート 月 100 件以上 / 無料→有料転換率 10% 以上 / 再利用企業率 50% 以上 / 平均実現単価 350 円以上 / レポート利用後の意思決定記録率 80% 以上。

> 最重要確認: 支払った人に「このレポートがなければ同じ判断ができたか」を聞き、**興味本位の閲覧か取引判断利用かを分ける**。

### 優先 4 — 訂正・取消・異議申立てのルールを固める

「改ざんできない」だけでは不十分。入力ミス・車台番号誤登録・部品番号誤り・写真取り違え・認識相違・作業キャンセル・再施工・返金・店舗閉鎖は必ず起きる。書き換えられないだけだと **誤情報が永久に残る**。

**必要な運用設計:**
- 訂正: 元データを消さず訂正履歴を追加
- 取消: 削除せず取消理由・日時を表示
- 異議申立て: 顧客・事業者・第三者が記録内容に異議を申し立て可能
- 権限管理: 発行者 / 顧客 / 車両所有者 / 閲覧者 / Ledra 運営者が何を見て何を変えられるか
- 所有者変更: 売買後、新所有者が履歴へアクセスする方法
- データ保存期間: 証明データ・画像・署名・アクセス履歴を何年保存するか

**クリア条件（仮）:** 利用規約 / プライバシーポリシー / 訂正・取消規程 / 異議申立て規程 / データ保存規程 / 所有者変更フロー / リーガルレビュー / インシデント対応手順 / データ開示請求手順。

> 保険会社・中古車大手は機能では導入しない。**「間違ったデータが登録されたとき誰がどう責任を持つか」** を必ず確認する。

### 優先 5 — 第三者が本当に使うか検証する

発行店舗以外が意思決定に使わなければ、Ledra は店舗向け SaaS のまま。

**最初の PoC 候補:**
- 中古車買取（高額車・カスタム車・コーティング施工車・用品装着車・修理歴判断が難しい車）→ 査定時間・査定価格・確認項目・追加質問数・買取後トラブルを検証
- 中古車小売 → 顧客説明時間・成約率・問い合わせ数・保証加入率・履歴付き価格差を検証
- 保険・保証 → 審査時間・写真不足率・修理内容確認時間・差戻し率・重複請求検出を検証

**クリア条件（仮）:** PoC 実施企業 3 社以上 / 1 社当たり 100 件以上 / 有料 PoC 1 社以上 / 継続利用意向 70% 以上 / 判断時間削減 20% 以上 / 差戻し・確認連絡削減 20% 以上。

> 無料 PoC で終わらせず、**少額でも実際に支払ってもらう** ことが重要。

### 最優先の次に解く課題（6〜8）

| 順位 | 課題 | 失敗した場合 |
|---|---|---|
| 6 | 車両履歴密度（1 台複数件） | 履歴 DB にならない |
| 7 | 外部連携 API（車台番号検索・証明概要取得・レポート発行・画像取得・真正性確認・Webhook・利用履歴・法人請求） | 業界基盤にならない |
| 8 | 中立性（公開検証方法・第三者監査・外部有識者・仕様公開・一般社団法人との役割分離） | 大手連携・標準化で疑問を持たれる |

> 7 の履歴密度は初期目標 20〜30%（`2件以上の証明を持つ車両数 ÷ 登録車両数`）。8 の中立化は「今すぐ法人設立」ではなく、先に実績を作ってから中立組織を設計する。

### いま着手を急がなくてよいもの（分散を避ける）

自動車外への本格展開 / 海外展開 / 行政認定 / 業界標準化 / 大規模 AI 査定 / 車両スコア / 店舗信頼スコア / 金融・残価モデル / 複数ブロックチェーン対応 / 大規模 IoT 連携。
→ **基礎データの品質と有料利用実績ができた後** に進める。

## 10. 最初の到達ゲート

次の状態を最初のゲートに設定する:

> **50 店舗が継続利用し、5,000 件以上の品質の揃った証明が発行され、3 社以上の第三者企業が実際の取引判断で有料利用している状態。**

ここまで到達すれば、Ledra は「証明書を発行できるサービス」から「**証明が実際の取引で使われるサービス**」へ移行したと判断できる。

## 11. 公開／非公開の切り分け

- **公開版:** 自動車業界の課題 / マイルストーン / KPI / 中古車・保険・オークション展開 / 他業界への展開構想。非公開領域は「将来技術領域」とだけ記載。
- **投資家・提携先向け機密版:** 非公開機能の詳細 / 独自技術 / データ取得方法 / AI モデル / 特許との関係 / 具体的な市場規模 / 提携候補 / 開発ロードマップ。

**中心メッセージ:** Ledra は施工証明書を発行する SaaS から始まる。証明が蓄積されると車両履歴になり、履歴が取引・保険・保証で使われると信用データになる。その仕組みは自動車に限らず、整備・施工・修理履歴が価値を左右するすべての高価値資産へ展開できる。

## 12. 未検証の外部事実（要確認リスト）

本文の `【要確認】` を集約。**本セッションでは検証していない。** 投資家・行政向け資料や意思決定の根拠に使う前に一次情報で確認すること（推測で事実を補わない）。

1. 国土交通省が電子点検整備記録簿を解禁し、点検整備記録を長期保存する「生涯記録簿」利用を推奨しているか。
2. 車体整備で作業内容・画像の保存、透明性向上が制度的に進んでいるか。
3. 経済産業省が電池パスポートのデータ管理システム・トレーサビリティ・ガイドラインを実証しているか。
4. 自動車部品サプライチェーンで企業間データ連携・トレーサビリティの実証が行われているか。
5. EU の Digital Product Passport（DPP）Registry の稼働時期・対象範囲・仕様（製品識別/修理保守/安全性/構成材料）。
6. 国交省の ICT 施工が試行から本格運用・原則化に向かう時期。
7. 国交省が無人航空機の特定飛行に飛行日誌（飛行記録/日常点検/点検整備記録の様式）を求めているか。
8. 航空分野の電子整備記録移行の状況（電子署名・記録完全性・セキュリティ・システム間移行の課題）。

> KPI・件数・金額はすべて **目標値（仮）** であり、実測値ではない。実績が出たら `docs/context/RELEASE_LOG.md` / `LEDRA_CURRENT.md` 側で更新する。
