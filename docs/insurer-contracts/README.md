## 0. なぜこのパッケージが「スムーズ化」に効くのか

日系大手保険会社との契約が遅延する典型要因は、(1) 当社側に「すぐ出せる雛形」が無く都度ゼロから作る、(2) 相手法務・調達の定番要求（DPA・監査・SLA・損賠上限・FSA 立入）に対する**当社の回答が決まっていない**、(3) 契約の**締結順序とタイミング**が曖昧で稟議が滞る、の 3 つ。

本パッケージは上記を潰すために、**契約スタック全体を締結順に並べ、各契約の条文ドラフトと当社の確定ポジションを事前に用意**する。相手から雛形が出てきても「当社の差分はここ」と即答できる状態を作る。

## 1. 契約スタックの全体像と締結順序

`docs/ledra-goals-strategy-2026-05.md` §3.3 の funnel に対応:

```
リード → 初回MTG → デモ → ①NDA → ②PoC合意書 → PoC実施 → ③本番接続契約(+④DPA +⑤SLA) → 課金開始
                        └ フェーズ1 ┘            └────────── フェーズ2〜3 ──────────┘
```

| # | ファイル | 契約名 | 締結タイミング | 対応フェーズ（lighthouse doc） | 拘束力 |
|---|---|---|---|---|---|
| ① | [`01-nda.md`](./01-nda.md) | 秘密保持契約書（NDA） | 初回〜2 回目 MTG 後 | フェーズ 1 冒頭（§4.2） | 有 |
| ② | [`02-poc-agreement.md`](./02-poc-agreement.md) | 実証実験（PoC）に関する合意書 | NDA 締結後 | フェーズ 1（§4.3） | 限定的（本番採用義務なし） |
| ③ | [`03-service-agreement.md`](./03-service-agreement.md) | サービス利用契約書（本番接続・基本契約） | PoC 成功後 | フェーズ 2 終端〜3（§8.4） | 有 |
| ④ | [`04-dpa.md`](./04-dpa.md) | 個人データの取扱いに関する契約（DPA・保険会社版） | ③ と同時 | フェーズ 2（§5.3 / §13） | 有 |
| ⑤ | [`05-sla.md`](./05-sla.md) | サービスレベル合意書（SLA・③の別紙） | ③ と同時 | フェーズ 2（§15） | 有（③に従属） |

> ④ DPA・⑤ SLA は ③ 本番接続契約の**別紙**として一体で締結する（③ 第 9 条・第 10 条で引用）。独立番号で管理するのは、相手法務が別書面化を求めるケースが多いため。

### 1.1 締結順序の原則

- **NDA は相手の雛形を起点に修正**する（日系大手は自社雛形を通したい傾向。`lighthouse §4.2`）。当社雛形（01）は「当社から先に出す必要がある／相手に雛形が無い」場合のフォールバック。
- **PoC 合意書には「本番採用義務なし」を明記**する。これが無いと相手法務が動かない（`lighthouse §4.3`）。同時に「成功時の本番接続契約への移行（努力義務）」を残す。
- **本番接続契約・DPA・SLA は 3 点セットで同時締結**。バラすと締結日がずれて課金開始が遅れる。

## 4. 交渉レッドフラグ（即エスカレ）— 全契約共通

以下が条文に出たら、署名前に **CEO + 弁護士へ即エスカレ**（`lighthouse §13.3`）:

- [ ] 全データ／ソースコードの提出義務
- [ ] 独占的取引義務（他保険会社との契約禁止）
- [ ] 無償永続ライセンス／業務委託先選定権の譲渡
- [ ] 損害賠償の上限なし／結果的損害も含む
- [ ] 発注側のみの事前通知なし即時解約権・一方的価格改定権
- [ ] 当社の特定従業員アサインに対する拒否権（人事承認権）

1. このフォルダを複製し、`【甲】` 等のプレースホルダを対象保険会社の値で差し替える。

## 6. 相手雛形（甲側ドラフト）への差分当て込み手順

日系大手保険会社は自社の契約・NDA・DPA 雛形を起点にしたがる（`lighthouse §4.2`）。相手雛形が来たら、当社雛形（01〜05）に差し替えようとせず、**当社の死守項目だけを相手雛形に当て込む**のが最短。

### 6.1 基本フロー（相手雛形受領 → 締結）

```
1. 受領した相手雛形を 01〜05 の当社条文と章ごとに対照（マッピング）
2. §4 レッドフラグを最優先でスキャン → 1 つでもあれば CEO + 弁護士へ即エスカレ（残れば撤退）
3. 下表「必ず当て込む差分」を相手雛形に赤入れ（当社ポジションを反映）
4. 「素通し項目」(6.3) は争わず相手文言を尊重 → 交渉点を絞る
5. 顧問弁護士レビュー → 差分のみを相手法務と協議（全文でなく差分表で議論）
```

### 6.2 契約別「必ず当て込む差分」（相手雛形でも死守）

| 契約 | 当て込む差分（当社ライン） | 出典 |
|---|---|---|
| **NDA**（01） | 目的を業務検証に限定／期間 24 ヶ月以上／独占・competing 制限を削除／監督官庁開示時の事前通知を復活 | 01 社内メモ |
| **PoC**（02） | 本番採用義務なしを明記／14 日前解約を双方対等に／PoC データ削除 60 日 | 02 社内メモ |
| **本番接続契約**（03） | 損賠上限＝一般 2 倍・漏えい等 3 倍スーパーキャップ・上限なし拒否／支払 30〜60 日（90 日拒否）／解約予告を双方対等／独占拒否／加盟店 ARR は当社直契約を死守／データの統計利用権を死守 | 03 第 17 条 社内メモ |

### 6.3 素通しでよい（争点化しない）項目 — スピード化

以下は当社雛形と相手雛形で原則一致するため、相手文言を尊重し交渉点を増やさない:

- 準拠法・管轄（東京地裁）
- 反社会的勢力の排除条項
- 個人情報保護委員会・金融庁（FSA）への報告協力
- 不可抗力・権利義務譲渡禁止の一般条項

### 6.4 差分が当社の死守ラインを越えたら

§4 レッドフラグ、または各契約 社内メモの「呑まない」項目が削れない場合は、`docs/lighthouse-sompo-japan.md` §19（撤退・縮小・延期判断）・§1.3（撤退ライン）に従う。**1 つでも残るなら撤退判断**。
