# 証明書が発行されるまでの流れ

このドキュメントでは、Ledra で証明書が作られてからお客様の手に届くまでの流れを、
**誰が何をするのか**に注目して説明します。

---

## 全体の流れ（かんたん図）

```
お客様が来店
    ↓
スタッフが証明書を作成（下書き）      ← スタッフの作業
    ↓
写真をアップロード（1枚以上必須）     ← スタッフの作業
    ↓
AIが写真の品質をチェック（※オプション）← AIの自動処理（設定時のみ）
    ↓
スタッフが「公開する」ボタンを押す     ← スタッフの作業
    ↓
証明書が発行される（有効になる）
    ↓
裏側で自動処理が動く                  ← システムの自動処理
  ・提携先への通知
  ・ブロックチェーンへの記録
  ・お客様へのフォローアップ通知
```

---

## 各ステップの詳細

### ステップ 1：証明書の下書きを作る

| 項目 | 内容 |
|------|------|
| **誰がやるか** | **スタッフ**（または管理者） |
| **どこで** | 管理画面 → 証明書 → 新規作成 |
| **何をするか** | お客様の名前、車両情報、施工内容、保証期間などを入力する |

**ポイント**
- この時点では証明書はまだ「**下書き**」の状態です
- 写真がなくても下書きは保存できます
- 一部の API 経由では契約プランの発行上限がチェックされます（管理画面からの作成では現在未適用）

> **AI の補助（オプション）**：予約が完了した時に、AI が過去の似た証明書を参考にして
> 下書きの内容を自動で提案してくれる機能もあります（設定でオンにした場合のみ）。
> ただし、AI が作った下書きはあくまで「提案」で、スタッフが確認・修正してから使います。

---

### ステップ 2：写真をアップロードする

| 項目 | 内容 |
|------|------|
| **誰がやるか** | **スタッフ** |
| **どこで** | 証明書の編集画面 |
| **何をするか** | 施工写真を **最低1枚** アップロードする |

**ポイント**
- **写真が1枚もないと、証明書は発行できません**（これが一番大事なルール）
- 写真はアップロード時に自動でハッシュ値（デジタル指紋）が計算され、改ざん防止に使われます

---

### ステップ 3：AI が写真の品質をチェックする（オプション）

| 項目 | 内容 |
|------|------|
| **誰がやるか** | **AI**（自動） |
| **何をするか** | アップロードされた写真を AI が分析して、品質を判定する |
| **前提条件** | テナント設定で「写真の自動品質チェック」がオンになっている場合のみ動作（**デフォルトはオフ**） |

**チェック内容**（有効化されている場合）
- 写真の内容が施工に関係しているか
- 暗すぎないか、ぼやけていないか
- 撮影角度は適切か

**判定結果は3種類**

| 判定 | 意味 | 発行できるか |
|------|------|-------------|
| **合格（Pass）** | 問題なし | はい |
| **警告（Warn）** | 気になる点あり（暗いなど） | はい（警告表示あり） |
| **不合格（Block）** | 必須項目が不足 | いいえ（修正が必要） |

> この機能が有効化されていない場合、このステップはスキップされます。
> また、AI チェックが内部エラーで失敗した場合も「判定できませんでした」として通過します。

---

### ステップ 4：証明書を発行する（公開）

| 項目 | 内容 |
|------|------|
| **誰がやるか** | **スタッフ**（staff 権限以上） |
| **どこで** | 証明書の新規作成画面（写真アップロード後） |
| **何をするか** | 作成フォームの「公開する」ボタンを押す |

**システムが自動で確認すること**
1. 写真が1枚以上あるか → なければエラーで中止
2. 操作者の権限は十分か → staff 以上が必要
3. 状態の変更は正しいか → 「下書き → 有効」の変更のみ許可

**発行が成功すると**、証明書の状態が「**下書き**」から「**有効**」に変わります。

---

### ステップ 5：発行後の自動処理

証明書が発行されると、**システムが裏側で自動的に**以下の処理を行います。
スタッフやお客様が何かする必要はありません。

#### 5-1. 提携先への自動通知

| 項目 | 内容 |
|------|------|
| **誰がやるか** | **システム**（自動） |
| **何をするか** | 提携先（保険会社など）にメールで証明書発行を通知する |
| **タイミング** | 発行直後（キューに入れて非同期で処理） |

#### 5-2. ブロックチェーンへの記録（アンカリング）

| 項目 | 内容 |
|------|------|
| **誰がやるか** | **システム**（自動・夜間バッチ） |
| **何をするか** | 証明書のデジタル指紋をブロックチェーン（Polygon）に記録する |
| **タイミング** | 毎日深夜 3:10（JST）にまとめて処理 |
| **目的** | 「この証明書がこの時点で存在していた」ことを第三者が検証できるようにする |

**仕組み（かんたん説明）**

```
証明書のデータ → ハッシュ化（個人情報は除外）
    ↓
複数の証明書のハッシュをまとめて「Merkle ツリー」を構築
    ↓
ツリーのルート（まとめた値）をブロックチェーンに1回で記録
    ↓
各証明書に「証明パス（Merkle Proof）」を保存
```

> この機能は環境設定でオン/オフを切り替えられます。
> オフの場合でも証明書の発行には影響しません。

#### 5-3. お客様へのフォローアップ通知

| 項目 | 内容 |
|------|------|
| **誰がやるか** | **システム**（自動） |
| **何をするか** | 発行後のフォローアップ通知をお客様に送信する |
| **条件** | テナントの「発行時に通知を送る」設定がオンの場合のみ |
| **タイミング** | 発行時に通知キューに登録され、フォローアップ用の定期処理で送信される |

> 通知の送信はキュー登録と定期処理の2段階で行われるため、
> 発行直後ではなく少し時間が経ってから届きます。

## 特別な操作

### 証明書を無効にする（ボイド）

| 項目 | 内容 |
|------|------|
| **誰がやるか** | **スタッフ**（staff 権限以上） |
| **いつ使うか** | 内容に誤りがあった場合や、取り消しが必要な場合 |
| **何が起きるか** | 証明書の状態が「有効」→「無効」に変わる |

### 無効にした証明書を再発行する

| 項目 | 内容 |
|------|------|
| **誰がやるか** | **管理者のみ**（admin 権限が必要） |
| **注意点** | 写真が1枚以上必要（再チェックされる） |
| **何が違うか** | 通知や提携先連絡は再度送られない（重複防止） |

---

## 権限のまとめ

| 操作 | スタッフ | 管理者 | AI | お客様 |
|------|:-------:|:------:|:--:|:------:|
| 証明書を作成（下書き） | OK | OK | 提案のみ | - |
| 写真をアップロード | OK | OK | - | -（※） |
| 写真の品質チェック | - | - | 自動 | - |
| 証明書を発行（公開） | OK | OK | - | - |
| 証明書を無効化 | OK | OK | - | - |
| 無効 → 再発行 | - | **OK** | - | - |
| ブロックチェーン記録 | - | - | - | - |
| 証明書を確認・検証 | OK | OK | - | OK |

> 「-」はその操作ができないことを意味します。
> （※）写真のアップロードはテナントに所属するメンバーであれば実行可能です。
> ブロックチェーン記録はシステムが自動で行うため、誰の操作も不要です。

---

## お客様の関わり方

お客様は証明書の作成・発行プロセスには直接関与しません。
お客様ができることは以下の通りです：

1. **証明書を受け取る** — 発行後にフォローアップ通知（設定されている場合）で届く
2. **証明書を確認する** — 公開IDを使って証明書の内容を閲覧できる
3. **真正性を検証する** — ブロックチェーンの記録と照合して、改ざんされていないか確認できる

## よくある質問

**Q: 写真なしで発行できますか？**
A: いいえ。最低1枚の写真が必須です。写真がないと「公開する」ボタンを押してもエラーになります。

**Q: AI のチェックで不合格になったら発行できませんか？**
A: AI の品質チェックはあくまで参考情報です。AI がエラーを出しても発行自体はブロックされません（必須項目の不足は除く）。

**Q: ブロックチェーンの記録に失敗したら証明書はどうなりますか？**
A: 証明書の発行には影響しません。記録は非同期で行われるため、失敗しても証明書は有効なままです。

**Q: 一度無効にした証明書を元に戻せますか？**
A: はい。ただし管理者権限が必要です。スタッフ権限では再発行できません。
