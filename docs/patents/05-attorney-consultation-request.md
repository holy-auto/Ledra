## B. 回答してほしい質問（相談チェックリスト）

弁理士に明確化してほしい論点。優先度順。

### B-0. 発明6（ZKP 選択的開示）・発明7（確定ゲート）— 最優先（未公開）
- [ ] 両発明は中核機構を**一切公開していない**（grep 0 件・2026-06-05 確認）。この前提で、
  **広い独立項**を狙えるか。先行技術（6: W3C VC/SD-JWT/BBS+/Merkle 選択的開示、7: 電子署名/
  GS1 シリアライゼーション/RFC3161）との距離をどう見るか。
- [ ] 発明6 の進歩性の核は「**開示/非開示/粗粒度を混在させた単一コミットメント木＋シークレット依存
  nonce による低エントロピー秘匿値保護＋車両部品×保険でのサーバ非依存検証**」。この組み合わせで成立するか。
- [ ] 発明7 の進歩性の核は「**記録作成主体が攻撃者である前提で、本人の物理的所持に束ねた確定を
  DB 層で運営者（service-role）にも例外なく強制し、連絡先出所で格下げする**」。この組み合わせで成立するか。
- [ ] 発明6・7・1 は実装上 `content_hash` で連結。**1 出願（複数独立項）に束ねる** vs 個別出願、
  どちらが費用対効果が高いか。

### B-1. 発明1（メタアンカー）— 出願時期を急ぐ（公開済みコンセプトあり）
- [ ] 「複数施工店をまたいで VIN で施工履歴を集約する」**コンセプト**を自社の公開ページ
  （`/features/timeline`：インデックス対象の完全公開、`/poc`：noindex だが URL 閲覧可・
  トヨタ提示想定）で **2026-05-04 から開示**している。これは新規性喪失に当たるか。
- [ ] 当たる場合、**新規性喪失の例外（30条）**は使えるか。起算日は「最初の公開日」だが、
  その実日（git コミットは 2026-05-04、**実デプロイ日／トヨタ提示日は要確認**）をどう特定すべきか。
- [ ] **メタアンカー機構の具体**（全 tx_hash をソート連結→SHA-256→**単一Tx**で集約記録／
  第三者が集約値を**サーバ非依存で再計算**して照合）は公開面に出ていない（grep 0件で確認）。
  この機構に請求項を絞れば、上記コンセプト開示の影響を避けて権利化できるか。
- [ ] `PASSPORT_PUBLIC_ENABLED=true`（本番公開）・HP更新・プレスの**前に出願**すべきという
  理解で正しいか。間に合わない場合の最善手は。

### B-2. 発明2（改ざん検出カスケード）・発明3（AI自動化ガードレール）
- [ ] 方法（アルゴリズム）自体は未公開。**ソフトウェア／ビジネス関連発明**として
  特許適格性（自然法則利用・ハードウェア資源との協働）を満たすか。
- [ ] 発明2は「二段カスケード」が一般概念のため進歩性が論点。**「両側スキップ＋集合レベル指標」**
  に絞った狭い請求項なら可能性があるか。単独出願 vs 発明1への従属、どちらが費用対効果が高いか。
- [ ] 発明3は要素技術が既知。**「3制御の統合＋非対称 failure semantics」**を進歩性の中心に
  据えられるか。
- [ ] 設定 UI が契約テナントに可視である点は、発明3の新規性に影響するか。

### B-3. 全体・実務
- [ ] 3件をまとめて出願 vs 個別出願、国内優先権・PCT の要否。
- [ ] 先行技術調査のお見積り（件数・範囲・期間）。
- [ ] 概算費用（調査／明細書作成／出願／中間対応）と標準的なスケジュール。

## F. 出願までの社内情報管理（重要）

出願前の公開は新規性を損なう。出願戦略が固まるまで、下記を**対外発信しない**。

- **U1〜U8（未公開の中核機構）**：メタアンカーのハッシュ仕様・単一Tx集約・サーバ非依存の
  集約値再計算／改ざん検出の三分類・両側スキップ／AI自動化の確信度降格・不可侵制約・費用遮断・
  非対称failure／**ZKP の選択的開示・コミットメント・nonce 設計（発明6）**／**本人所持証明に束ねた
  DB 強制確定・連絡先出所の格下げ・横断シリアル照合（発明7）** — ブログ・登壇・PoC追補・SNS・
  採用記事・**保険会社/OEM 向け資料**等で語らない。
- **`PASSPORT_PUBLIC_ENABLED=true` 化を保留**：発明1の `/v/`・検証API の本番公開は、
  出願戦略の確定後に。公開すると検証APIから機構が読み取れる。
  - 🔒 **実装済みのハードロック**：本番(production)の環境変数に **`PASSPORT_PATENT_HOLD=1`** を設定すること。
    これが立っている間は `PASSPORT_PUBLIC_ENABLED=true` を誤って入れても公開ルートは 404 のまま
    （`src/lib/passport/featureGate.ts`）。ロックを外すのは出願 GO/NO-GO 確定後、弁理士確認を通してから。
- **`/poc`・`/features/timeline` の追記凍結**：これ以上 VIN集約／メタアンカーに踏み込む記述を
  足さない（既存開示の範囲を広げない）。
- 公開面に手を入れる前に必ず [04 棚卸し](./04-disclosure-inventory.md) を更新し、弁理士確認を通す。
