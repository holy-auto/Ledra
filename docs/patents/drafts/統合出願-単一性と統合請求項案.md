# 統合出願：単一性（特37条）の検討と統合請求項案

> 目的：発明 06（ZKP選択的開示）・07（確定ゲート）・01（メタアンカー）を**1出願に束ねる**場合の請求項案と、その**単一性（発明の単一性・特許法37条）リスク**の整理。
> ⚠️ 単一性・分割の最終判断は弁理士。本書は戦略の選択肢提示。

---

## 0. 結論（先に）

- **原則は「個別3出願」を推奨**（優先度 06 → 07 → 01）。3発明は機構が大きく異なり、**1出願に束ねると単一性欠如（37条）の拒絶**を受け、結局**分割出願**になりやすい。
- **どうしても1出願にする場合**は、3発明を**「真正性パイプライン」という単一の技術的思想**でくくる（後述 §2）。共通の技術的特徴＝「**確定された記録の内容ハッシュが、集約と選択的開示に共通して供され、検証者がサーバ非依存で検証可能**」。それでも審査官が単一性を認めない可能性は残る。

---

## 1. 単一性（特37条）の要点と本件評価

- 1出願に複数の発明を含められるのは、それらが**単一の一般的発明概念**を形成するように連関している場合（**特別な技術的特徴＝STFを共有**）に限る。
- 本件の各機構は独立性が高い：
  - **07**＝本人所持証明に束ねたDB層の確定強制（情報セキュリティ）
  - **01**＝順序非依存ダイジェストの単一Tx集約＋第三者再計算（完全性証明）
  - **06**＝開示/非開示混在のコミットメントによる選択的開示（プライバシー）
- 共通点は「**車両証跡の暗号学的表現を分散台帳に記録し、サーバ非依存で第三者が検証可能とする**」だが、**この共通点は先行技術（ハッシュの台帳記録）に照らしてそれ自体ではSTFになりにくい**。
- → **個別出願なら各々が自分のSTFで自立**できる。束ねると「first invention のみ審査・残りは分割」となるリスク。

## 2. それでも1出願に束ねる場合の統合請求項案

**鍵**：3機構を「**内容ハッシュ（content_hash）を媒介に連結した一連のパイプライン**」として独立項1に書き、**連関（confirmが生むhashをaggregateとdiscloseが共通に使う）**を明示する。これにより「単一の一般的発明概念」を主張する。

### 【請求項１】（統合・システム）
　車両に係る証跡の真正性処理システムであって、
　部品の装着に関する記録の内容ハッシュをサーバ側で算出し、利用者本人の所持証明に束ねた電子署名の一致をデータベース層の制約により検証して当該記録を確定する確定手段であって、当該制約が特権を有するサービスアカウントに対しても例外を設けない確定手段と、
　確定された複数の記録に係るハッシュの集合を、正規化された車両識別子に基づき、重複排除及び所定順序のソートにより順序非依存に正規化して集約ダイジェストを算出し、単一のトランザクションとして分散台帳に記録する集約手段と、
　前記記録に関する複数のクレームに開示又は非開示の別を付してコミットし、当該コミットメントのルートを前記分散台帳に記録し、検証者から指定されたクレームの包含経路を、開示のクレームについてのみ値を付して提供する開示手段と、を備え、
　前記確定手段が確定した前記内容ハッシュが、前記集約手段及び前記開示手段に共通に供され、
　検証者が、前記システムのサーバに依存することなく、前記分散台帳の記録に基づき前記記録の真正性を検証可能とする、
　車両証跡真正性処理システム。

### 【請求項２】（確定手段＝07の独立形式）
　前記確定手段において、前記データベース層の制約が、(a) 署名が当該記録に紐づき署名対象ハッシュが現在の内容ハッシュに一致すること、(b) 署名の所持証明値が利用者の登録所持証明値に一致すること、(c) 署名の保証グレードが部品のリスクから導出した必要グレードを満たすこと、を検証する、請求項１に記載のシステム。

### 【請求項３】（07従属：連絡先出所格下げ）
　連絡先の出所が記録作成主体によるものである場合に到達可能な前記保証グレードを制限する、請求項２に記載のシステム。

### 【請求項４】（集約手段＝01の独立形式）
　前記集約手段が、互いに独立した複数の事業者が個別に記録したトランザクション識別子の集合を、正規化された車両識別子に基づき横断的に収集して前記集約ダイジェストを算出し、当該集約ダイジェストが既記録と一致する場合に前記単一のトランザクションの記録を行わない、請求項１に記載のシステム。

### 【請求項５】（01従属：第三者再計算）
　前記正規化された車両識別子と前記集約ダイジェストと前記集合とを外部に提供し、第三者が同一手順で再算出して照合可能とする、請求項４に記載のシステム。

### 【請求項６】（開示手段＝06の独立形式）
　前記開示手段が、各クレームの値と秘密値を鍵とする決定的関数により導出したノンスとに基づく葉コミットメントから木構造のルートを算出し、開示・非開示のクレームを単一の木構造内に混在して含む、請求項１に記載のシステム。

### 【請求項７】（06従属：粗粒度・存在＋包含）
　前記クレームが装着時刻を所定期間単位に丸めた粗粒度の時期クレームを含み、前記検証が前記ルートの前記分散台帳への記録済みを条件とする、請求項６に記載のシステム。

### 【請求項８・９】（方法・プログラム）
　請求項１の各手段が実行する処理を備える方法、及び当該方法をコンピュータに実行させるプログラム。

> 注：請求項2/4/6 は、各機構を**それぞれ独立に権利化できる足場**として配置。万一、統合の単一性が否定され分割になっても、各機構のクレームをそのまま分割出願へ移送しやすい構成にしてある。

## 3. 推奨戦略（現実解）

1. **個別3出願（推奨）**：06 → 07 → 01 を別出願。各々が自立したSTFを持ち、審査も明快。01は30条（[10](../10-art30-novelty-exception.md)）。
2. **親＋分割**：いずれかを親出願にし、審査で単一性を見ながら分割。費用は嵩むが取りこぼしにくい。
3. **国内優先権（特41条）の活用**：先に個別出願 → 1年以内に**改良・統合を加えた出願**で国内優先権を主張し、最先の出願日を確保しつつ束ねる（ただし統合側にも単一性は適用）。
4. **海外（PCT）**：PCTは単一性の運用が国内と異なる。海外を視野に入れるなら、束ね方・分割方針を弁理士と早期に設計。

→ **結論**：権利の堅牢性とコストのバランスから、**個別3出願（06優先）**が基本線。統合は「パイプライン（請求項1）」を別途のシステム出願として持つ選択肢として保持。
