# 提案: 保険募集「事前確認ポータル」(Insurance Pre-check) — 令和7年保険業法改正対応

作成日: 2026-07-04
参照記事: [令和8年6月施行 保険業法改正の概要と実務対応(BUSINESS LAWYERS・石田哲也弁護士)](https://www.businesslawyers.jp/articles/1472)

## 1. 改正の要点と、なぜ Ledra のユーザーに効いてくるか

令和7年(2025年)5月30日に改正保険業法が成立し、**令和8年(2026年)6月1日に施行済み**(= 既に現行法)。
背景は保険金不正請求事案(ビッグモーター) — **「中古車販売・自動車修理工場 × 損害保険代理店」の兼業**による修理費水増し請求 — と保険料調整行為事案(損保カルテル)。
Ledra の顧客層(整備・板金・コーティング・PPF 施工店)の多くは損保代理店を兼業しており、まさに今回の規制強化が念頭に置く業態。

主な改正内容と適用範囲:

| 改正項目 | 内容 | Ledra ユーザー(中小の兼業代理店)への効き方 |
|---|---|---|
| 特定大規模乗合損害保険代理店の体制整備義務(改正法294条の4) | 手数料等20億円以上等の大規模乗合代理店に、法令等遵守責任者・統括責任者の設置、苦情処理体制、内部通報・内部監査 | 直接の義務は大規模のみ(該当は全国500社程度) |
| 兼業業務の監視体制整備義務(改正法294条の4第4号イ) | 上記の大規模代理店のうち**自動車修理業(施行規則53条の14の3)を兼業**する場合、保険金支払に不当な影響を及ぼさないよう兼業業務を監視する体制 | 直接の義務は大規模のみ |
| **保険会社側の体制整備義務の強化(改正法100条の2の2)** | 兼業代理店の取引により顧客の利益が不当に害されることを防止する体制。内閣府令で**「体制不十分な兼業代理店に対する支払査定の厳格化」**、支払管理部門と営業部門の分離 | **ここが本丸。** 規模を問わず、体制を示せない兼業代理店は保険会社から支払査定を厳格化され、代理店管理・点検も強化される |
| 過度な便宜供与の禁止(改正法300条1項5号) | 「特別の利益の供与」から「過度な便宜供与」へ拡大、対象者に密接関係者(グループ企業等)を追加 | 全募集人が対象(広い) |
| 比較推奨販売の見直し(監督指針・施行規則の関連改正、いわゆるハ方式廃止・ロ方式一本化) | 「自店の推奨商品だから」での提案が不可に。**意向把握 → 意向に沿った選別 → 推奨理由の説明**とその**記録・証跡の保存**。※本体改正とは別に監督指針等で手当て(パブコメ結果公表待ちの部分あり) | 乗合代理店すべて |

つまり中小の兼業代理店にとっての実際の影響経路は「自社への直接義務」ではなく、**保険会社経由の締め付け**(体制不十分なら支払査定の厳格化・代理店点検の強化)と**比較推奨販売の証跡要求**。改正対応の実務は突き詰めると **「募集と修理の分離、そして募集プロセスの証跡をどう残し、どう示すか」** の問題になる。

これは Ledra が既に持つコア資産 — **電子署名 + RFC3161 タイムスタンプ + ブロックチェーンアンカリングによる改ざん検知可能な証跡管理** — と完全に同型。施工証明書で作った仕組みを保険募集プロセスに横展開するだけで、他の代理店システムにない差別化(改ざん検知付き募集証跡)になる。

## 2. 位置づけ(重要): Ledra は「契約締結システム」にはならない

保険契約の締結自体は保険会社の募集システム+書面で行われる(完成形の「本契約は対面で書面サイン」と一致)。
Ledra が担うのは **契約前の準備と証跡のレイヤー**:

- 事前見積りの提示・閲覧記録
- 重要事項説明(契約概要・注意喚起情報)の電磁的交付と受領・理解確認の証跡
- 意向把握・比較推奨理由の記録
- 更新時の新旧差分説明の記録
- 以上への **タイムスタンプ付き電子署名**

法令上の前提:
- 契約概要・注意喚起情報の**電磁的交付には顧客の事前承諾が必要**(承諾自体を記録する)
- 非対面での交付は、全文閲覧+チェックボックス等での**理解確認**を組み合わせれば可(損保協会ガイドライン)
- AI 音声・要約は**説明の補助**。交付書面の原文提示と募集人の説明責任は残る(AI の要約だけで完結させない)
- 推奨・比較の説明という募集行為は募集人資格者が行う前提。Ledra は配信・記録ツールに徹する

## 3. 完成形 → 既存資産マッピング

| 完成形の要件 | 実現方法 | 再利用する既存実装 |
|---|---|---|
| 事前見積りをいつでもどこでも確認 | 見積 PDF + プラン内容をトークン URL の顧客ページで公開 | 署名トークンページ `src/app/sign/[token]/`、公開ビュー `src/app/c/[public_id]/`、見積ドキュメント(`doc_type='estimate'`, `src/lib/ai/quoteFromVehicle.ts`) |
| 重要事項説明を AI が音声で説明 | 電磁的交付の承諾取得 → PDF 原文表示 + AI 要約 + **ブラウザ標準 Web Speech API で読み上げ**(依存ゼロ) + 節ごとの理解確認チェック | AI structured outputs `src/lib/ai/`。TTS は未実装 → まず Web Speech API、品質要求が出たらクラウド TTS に差し替え |
| 更新時に新旧保険内容の差分を説明 | 旧証券と新見積を AI で構造化抽出 → 差分表(保険料・補償・特約・免責)を顧客ページに表示、説明記録を保存 | AI 抽出パターン `src/lib/ai/`、更新時期リマインドは `src/lib/cron/serviceReminders.ts` の期日通知パターンを流用 |
| タイムスタンプ付き電子署名で事前同意 | 「意向確認」「重説受領・理解確認」「プラン同意」の3点に既存署名フローをそのまま適用 | `src/lib/signature/`(hash/session)、`src/lib/parts/tsa.ts`・`rfc3161.ts`、アンカリング `src/lib/anchoring/` |
| 本契約は対面・書面で最終締結 | 店頭では「事前証跡サマリ PDF」を出力し、確認+書面サインのみで完了 | PDF 生成 `src/lib/pdf/`、`pdfDocument.tsx` |
| LINE で完結 | トークン URL の送付・未読リマインド・更新案内を LINE 配信 | `src/lib/line/`(client/linkCustomer)、Webhook `src/app/api/webhooks/` |

新規に必要なのは実質「保険事前確認セッション」のデータモデルと顧客向け1画面+管理1画面のみ。署名・TSA・LINE・PDF・AI はすべて既存の呼び出し。

## 4. 段階提案

### Phase 1 — 事前見積り確認 + 電子署名(最小・現行業務を壊さない)
- `insurance_prechecks` テーブル(tenant_id, customer_id, 見積 PDF, 電磁的交付の承諾, ステータス, 署名セッション参照)
- 管理側: 見積 PDF を添付して事前確認セッションを作成 → LINE/メールでトークン URL 送付
- 顧客側: 見積閲覧 → 交付承諾チェック → タイムスタンプ付き電子署名(閲覧ログ付き)
- 店頭: 署名済みか一目で分かるステータス + 証跡サマリ PDF

現行の紙運用はそのまま残す(事前確認は任意の前置き)。既存署名フローに新しい書類種別を1つ足すのに近い規模。

### Phase 2 — 重説の電磁的交付 + AI 音声 + ロ方式の証跡
- 契約概要・注意喚起情報 PDF の交付 + 節ごとの理解確認チェックリスト
- AI 要約 + Web Speech API 読み上げ(原文常時表示、「要約は補助」の注記)
- 意向把握フォームと推奨理由の記録欄(ロ方式: 意向 → 選別 → 推奨理由の3点セットを証跡化)

### Phase 3 — 更新差分の AI 説明
- 旧証券 PDF + 新見積 PDF → AI 構造化抽出 → 差分表を顧客ページに表示
- 満期日ベースの更新リマインドを LINE 自動配信(serviceReminders のパターン流用)

### Phase 4(将来目標) — オンライン締結への接続と特典設計

**(a) 保険会社募集システムとの連携・オンライン締結**
オンライン締結自体は保険業法上禁止されていない(「対面・書面」は法律の要請ではなく、各保険会社の募集システムと代理店規程の制約)。大手損保は既に電子申込・ペーパーレス手続きを持っているため、現実的な到達手順は:

1. **引き継ぎ型(すぐ可能)**: Ledra の事前確認完了 → 保険会社の電子申込 URL へ誘導し、店側には「事前証跡サマリ + 申込完了チェック」を表示。締結は保険会社システム側で完結し、Ledra は前後の証跡を持つ
2. **連携型(提携が前提)**: 損保各社の募集システムに公開 API はないため、取扱保険会社1社とのパイロット提携から。Phase 1〜3 で蓄積した「改ざん検知可能な募集証跡」は、保険会社側の代理店管理義務(改正法100条の2の2)への説明材料になるため、提携交渉の材料そのものになる

対面・書面での締結は移行期間中も併存させ、保険会社・商品ごとに可能な方式を選べる設計にする。

**(b) 特典・優遇系の機能**
**保険契約を条件とした特典(値引き・キャッシュバック・過度な物品/役務の提供)は改正法300条1項5号の禁止行為(過度な便宜供与・特別利益の提供)に該当しうるため実装しない。** これは設計で回避できない法律上の線。実装するなら:

- 特典は**本業(整備・施工)側の顧客サービス**として設計し、保険加入の有無と紐付けない(例: 車検・点検リマインド、施工履歴に基づくメンテナンス案内 — 既存の `serviceReminders` の延長)
- 保険募集に付随する景品類は、各保険会社の代理店規程・損保協会ガイドラインの社会通念上相当な範囲に限られるため、機能化する場合は「特典が保険契約に条件付けられていないこと」をチェックするガードを入れる

## 5. 現場が楽になるポイント

1. **店頭時間の短縮**: 読み合わせ・検討・署名が事前に済み、来店時は本人確認+書面サインのみ
2. **監査・保険会社の代理店点検対応**: 意向把握〜重説〜同意の証跡がタイムスタンプ付きで自動保存され、点検時にそのまま提出できる
3. **更新業務の自動化**: 満期リマインド+差分説明が LINE で自動送付され、電話・郵送の追いかけが減る
4. **保険会社への体制アピール**: 改正法100条の2の2により保険会社は「体制不十分な兼業代理店」への支払査定を厳格化する。「修理と保険募集の記録が分離され、改ざん検知可能な証跡で管理されている」ことを示せる代理店は、査定・点検の面で不利益を受けにくい
