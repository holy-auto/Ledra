# 整備・部品交換の記録が完了するまでの流れ

このドキュメントでは、Ledra で部品交換や整備作業の記録が作られてから、
お客様の確認を経て完了するまでの流れを、
**誰が何をするのか**に注目して説明します。

> **施工証明書（コーティング・PPF など）のワークフローとは別の仕組みです。**
> 施工証明書については `certificate-workflow-guide.md` を参照してください。

---

## 全体の流れ（かんたん図）

```
部品を発注する                        ← スタッフの作業
    ↓
部品が届く（入荷）                    ← スタッフが受領処理
    ↓
整備・部品交換を実施                  ← スタッフの作業
    ↓
作業記録を登録（写真・証拠つき）      ← スタッフの作業
    ↓
AIが不正チェック（自動）              ← AIの自動処理
  ・シリアル番号の使い回し検出
  ・写真の重複検出
    ↓
納品書をアップロード・照合            ← スタッフの作業（＋AIの自動処理）
    ↓
お客様に確認を依頼                    ← スタッフが依頼
    ↓
お客様がOTPで本人確認＋電子署名       ← お客様の作業
    ↓
記録が確定（以後変更不可）
    ↓
ブロックチェーンに記録（自動）        ← システムの自動処理
```

---

## 施工証明書との大きな違い

| 項目 | 施工証明書（コーティング等） | 部品交換の記録 |
|------|--------------------------|--------------|
| **お客様の確認** | 任意（なくても発行可能） | **必須**（OTP＋電子署名） |
| **変更の可否** | 無効化→再発行が可能 | 確認後は**完全に凍結**（無効化のみ） |
| **不正チェック** | 写真の品質チェック（オプション） | シリアル重複・写真重複・三者照合 |
| **証拠の管理** | 写真のみ | 写真＋納品書＋旧部品写真など多種 |
| **ブロックチェーン** | 証明書単位で1回 | 部品ごと＋車両ごとの2段階 |

---

## 各ステップの詳細

### ステップ 1：部品を発注する

| 項目 | 内容 |
|------|------|
| **誰がやるか** | **スタッフ** |
| **どこで** | 管理画面 → 部品発注 |
| **何をするか** | 部品名、品番、仕入先、数量、単価を入力して発注する |

**発注の状態**

| 状態 | 意味 |
|------|------|
| 発注済み（ordered） | 仕入先に注文した |
| 一部入荷（partial） | 数量の一部だけ届いた |
| 入荷完了（received） | すべて届いた |
| キャンセル（cancelled） | 発注を取り消した |

---

### ステップ 2：整備・部品交換を実施して記録する

| 項目 | 内容 |
|------|------|
| **誰がやるか** | **スタッフ** |
| **どこで** | 管理画面 → 作業記録 |
| **何をするか** | 交換した部品の情報と証拠写真を登録する |

**登録する内容**
- 部品名、品番（GTIN）、ロット番号、シリアル番号
- 数量、金額
- 取り付けた車両・お客様の情報
- 証拠写真（最大50枚）

**証拠写真の種類**

| 種類 | 説明 |
|------|------|
| 取付写真（install_photo） | 新しい部品を取り付けた状態の写真 |
| 状況写真（context_photo） | 作業の全体的な状況がわかる写真 |
| 旧部品写真（old_part_photo） | 取り外した古い部品の写真 |
| 納品書（delivery_note） | 仕入先からの納品書 |
| 取外し部品（removed_part） | 取り外した部品の状態を記録 |

**ポイント**
- シリアル番号は生のデータでは保存されず、暗号化された指紋（HMAC）として記録されます（情報漏えい対策）
- 証拠写真は**追加のみ可能**で、一度登録したものは削除・差し替えできません
- 登録時にシステムが自動で「コンテンツハッシュ」（デジタル指紋）を計算します

**部品の種類による確認レベルの違い**

| 部品の種類 | 確認方法 | 例 |
|-----------|---------|-----|
| シリアル付き部品（serialized） | **お客様本人のOTP必須** | エンジン、ミッション |
| 高額部品（10万円超） | **お客様本人のOTP必須** | 高級パーツ |
| ロット管理部品（lot_only） | 店舗連絡先でのOTP可 | ブレーキパッド |
| 消耗品（consumable） | 簡易確認で可 | オイル、フィルター |

---

### ステップ 3：AI が不正チェックを行う

| 項目 | 内容 |
|------|------|
| **誰がやるか** | **AI**（自動） |
| **何をするか** | 登録された記録に不正がないか自動でチェックする |

**チェック内容**

| チェック項目 | 何を見ているか | 深刻度 |
|------------|--------------|--------|
| シリアル番号の使い回し | 同じシリアルが他の作業でも使われていないか（全テナントで検出） | 重大 |
| 写真の重複 | 同じ写真が別の作業記録にも使われていないか | 重大 |
| 数量の不一致 | 取付数と納品数が合っているか | 重大 |
| 金額のずれ | 請求額と仕入額が5%以上ずれていないか | 警告 |
| 写真の改ざん | 写真が加工されていないか | 重大 |
| タイムスタンプの異常 | 写真の撮影日時に矛盾がないか | 警告 |

**検出結果は管理画面の「部品整合性」ダッシュボードで確認できます。**

---

### ステップ 4：納品書をアップロードして照合する

| 項目 | 内容 |
|------|------|
| **誰がやるか** | **スタッフ**がアップロード → **AI**が自動で照合 |
| **どこで** | 作業記録の詳細画面 |
| **何をするか** | 仕入先からの納品書をアップロードして、記録と照合する |

**三者照合（スリーウェイマッチング）**

```
取り付けた部品 ←→ 納品書の内容 ←→ 請求額
```

この3つが一致しているかを自動チェックします。

| 不一致の例 | 深刻度 | 意味 |
|-----------|--------|------|
| 取付数 > 納品数 | **重大** | 納品されていない部品を取り付けたことになっている |
| 取付部品が納品書にない | **重大** | 仕入記録がない部品を使っている |
| 請求額 ≠ 取付数 × 単価 | 警告 | 過大・過少請求の可能性 |

> AI による OCR（文字読み取り）で納品書の内容を自動抽出します（テナントの設定でオンの場合）。
> 手動で照合内容を入力することもできます。

---

### ステップ 5：お客様に確認を依頼する

| 項目 | 内容 |
|------|------|
| **誰がやるか** | **スタッフ**が依頼を開始する |
| **どこで** | 作業記録の詳細画面 |
| **何をするか** | お客様に部品交換の内容を確認してもらうための依頼を送る |

**確認依頼の送信方法（自動で最適なものが選ばれる）**

| 方法 | 優先度 | 説明 |
|------|--------|------|
| お客様の携帯電話（SMS） | 高 | お客様本人の電話番号にOTPを送信 |
| LINE | 中 | お客様がLINE連携している場合に利用 |
| 店頭タブレット | 低 | 消耗品など低リスク部品のみ利用可 |

**重要な仕組み：連絡先の出どころチェック**
- お客様自身が登録した電話番号 → 本人確認として有効
- スタッフが代理で登録した電話番号 → 最高レベルの確認には使えない（なりすまし防止）

---

### ステップ 6：お客様が確認・署名する

| 項目 | 内容 |
|------|------|
| **誰がやるか** | **お客様** |
| **どこで** | スマートフォンの確認画面 |
| **何をするか** | OTP入力 → 内容確認 → 電子署名 |

**確認の流れ**

```
① お客様の電話にOTP（6桁の数字）が届く
    ↓
② お客様が確認画面でOTPを入力（本人確認）
    ↓
③ 交換した部品の内容を画面で確認
    ↓
④ 「確認する」ボタンを押す（電子署名）
    ↓
⑤ RFC 3161 タイムスタンプが付与される
   （第三者機関が「この時点で署名された」ことを証明）
    ↓
⑥ 記録が「お客様確認済み」に変わる → 以後変更不可
```

**確認完了後にシステムが検証すること**
1. 電子署名が有効か
2. 署名時のデジタル指紋が記録時のものと一致するか（改ざんされていないか）
3. 署名者の電話番号がお客様本人のものか
4. 確認レベルが部品の種類に求められるレベル以上か

**すべての条件を満たした場合のみ、記録が「確認済み」に変わります。**

---

### ステップ 7：記録が確定する（凍結）

| 項目 | 内容 |
|------|------|
| **誰がやるか** | **システム**（自動） |
| **何が起きるか** | 記録が完全に凍結され、誰も変更できなくなる |

**凍結後にできないこと**
- 部品名、数量、金額の変更
- 証拠写真の削除・差し替え
- デジタル指紋や署名の変更
- 管理者でも変更不可（システム権限でも上書きできない）

**凍結後にできること**
- 記録の無効化（void）のみ可能（無効理由の入力が必要）

> これは会計の「赤伝票」と同じ考え方です。
> 間違いがあった場合は、元の記録を無効化して新しい記録を作り直します。

---

### ステップ 8：ブロックチェーンに記録する

| 項目 | 内容 |
|------|------|
| **誰がやるか** | **システム**（自動・定期処理） |
| **何をするか** | 確認済みの記録をブロックチェーン（Polygon）に書き込む |
| **タイミング** | 定期的な cron ジョブで処理 |

**2段階の記録方式**

| 方式 | 対象 | 内容 |
|------|------|------|
| **部品ごとの記録** | シリアル付き部品・高額部品 | 1部品 = 1トランザクション |
| **車両ごとのまとめ記録** | 同一車両の全確認済み部品 | 車両単位でハッシュをまとめて1トランザクション |

> 車両ごとのまとめ記録は、トランザクション費用を節約するための仕組みです。

## 不正防止の仕組みまとめ

| 想定される不正 | どうやって防ぐか |
|--------------|----------------|
| 偽の写真を使う | AI が写真の重複・加工を検出 |
| 同じ部品を複数の作業で使い回す | シリアル番号の指紋を全テナントで照合 |
| 納品されていない部品を請求する | 三者照合（取付・納品・請求）で不一致を検出 |
| お客様に無断で確認済みにする | お客様本人の電話にOTPを送信して本人確認 |
| スタッフがお客様になりすます | 連絡先の登録者を記録し、スタッフ登録の番号では最高レベルの確認ができない |
| 確認後にこっそり内容を変更する | 確認済みの記録はデータベースレベルで完全凍結 |
| 記録自体を改ざんする | ブロックチェーンに記録されたハッシュと照合して検証可能 |

## 権限のまとめ

| 操作 | スタッフ | 管理者 | AI | お客様 |
|------|:-------:|:------:|:--:|:------:|
| 部品を発注する | OK | OK | - | - |
| 作業記録を登録する | OK | OK | - | - |
| 証拠写真をアップロード | OK | OK | - | - |
| 不正チェック | - | - | 自動 | - |
| 納品書をアップロード | OK | OK | - | - |
| 三者照合 | OK | OK | 自動（OCR） | - |
| お客様に確認を依頼 | OK | OK | - | - |
| OTP入力・電子署名 | - | - | - | **本人のみ** |
| 確認済み記録の閲覧 | OK | OK | - | OK |
| 確認済み記録の無効化 | OK | OK | - | - |
| 確認済み記録の編集 | **不可** | **不可** | **不可** | **不可** |
| ブロックチェーン記録 | - | - | - | - |

> ブロックチェーン記録はシステムが自動で行うため、誰の操作も不要です。
> 確認済みの記録は、管理者であっても編集できません（無効化のみ可能）。

## お客様の関わり方

部品交換では、お客様の関与が**必須**です（施工証明書とは異なります）。

| お客様がすること | タイミング | 必須か |
|----------------|-----------|--------|
| OTPを入力して本人確認 | スタッフから依頼が届いた時 | **必須** |
| 交換内容を確認して電子署名 | OTP入力後 | **必須** |
| 確認済みの記録を閲覧 | いつでも | 任意 |

## メンテナンスパック（回数券）

部品交換とは別に、定期メンテナンス用の「回数券」の仕組みもあります。

| 項目 | 内容 |
|------|------|
| **誰が作るか** | **スタッフ**（または管理者） |
| **何か** | 「3年フルメンテナンス」のような、決まった回数分のサービスをまとめて販売する仕組み |
| **使い方** | 予約（作業）ごとにチケットを1枚消費する |

**パックの状態**

| 状態 | 意味 |
|------|------|
| 有効（active） | 使用可能 |
| 期限切れ（expired） | 有効期限を過ぎた |
| 使い切り（exhausted） | 全チケットを使い切った |
| キャンセル（cancelled） | 取り消された |

## よくある質問

**Q: お客様の確認なしで記録を完了できますか？**
A: いいえ。部品交換の記録は、お客様のOTP入力と電子署名が必須です。これは不正防止のための重要な仕組みです。

**Q: 確認済みの記録に間違いがあった場合はどうしますか？**
A: 元の記録を「無効化」して、正しい内容で新しい記録を作り直します。確認済みの記録を直接編集することはできません。

**Q: シリアル番号はデータベースに保存されますか？**
A: 生のシリアル番号は保存されません。暗号化された指紋（HMAC）のみが記録され、同じシリアルの使い回しを検出するために使われます。

**Q: お客様がスマートフォンを持っていない場合は？**
A: 消耗品など低リスクの部品であれば、店頭タブレットでの確認が可能です。シリアル付き部品や高額部品はお客様本人の電話での確認が必須です。

**Q: ブロックチェーンの記録に失敗したらどうなりますか？**
A: 記録の確定には影響しません。ブロックチェーンへの記録は非同期で行われ、次回の定期処理で再試行されます。
