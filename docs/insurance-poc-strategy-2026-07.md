## 0. 一行サマリ（結論）

保険 PoC には設計上の穴があった。**結論は「拡散してから」ではなく「検証項目を母数の要否で割る」こと。** そして決定的な制約 — **現在の 12 店舗はコーティング・PPF 中心で、保険修理を扱う板金店が 1 店も含まれない（堀越確認済み）** — により、目玉だった「修理案件の確認工数削減 PoC」は **いま検証すらできない**（対照実験に使う保険修理案件が存在しない）。

一方、いまのコーティング・PPF データで **今日から成立する別用途** がある: **事故前の車体状態の証明**（施工前の全周写真が時刻固定・改ざん不可で残る）。保険会社が構造的に持てないデータで、査定で最も揉める「既存損傷か事故損傷か」の切り分けに直接効く（※推論・要確認）。

推奨: **A（事故前状態証明で今日から会話を始める）＋ B（自力で板金店 3 社を入れる）を併走**。C（保険会社に提携板金工場の紹介を頼む）は実績ゼロでは順序が逆。

## 1. 元の PoC 設計の穴 — 検証したいものが 2 つ混ざっていた

「保険 PoC」を一括りにしていたが、検証項目ごとに必要な母数が違う。

| 検証項目 | 必要な母数 | いま実行できるか |
|---|---|---|
| ① 確認工数の削減時間 | 20〜30 件で足りる（対照実験） | 本来できる（ただし後述の板金店ギャップで不可に） |
| ② 見積と施工記録の一致率 | 数十件 | 本来できる（同上） |
| ③ 不正・疑義の検知 | 数千件以上 | できない |

- **①は対照実験なので案件数は要らない。** 同じ案件を「Ledra あり／なし」で査定担当者に見てもらい、ストップウォッチで測るだけ。n=30 あれば有意差は出る（※統計的主張は未検証・要確認）。
- **③だけが母数を要求する。** そして③は、リーフレットで「不正検知は 1 件も見込まずに ROI が成立する」と設計した通り、**PoC の合格判定には不要**。

> つまり「母数がないと PoC できない」は誤り。母数が要るのは③だけで、③は合格条件に入れていない。

## 2. より深刻な穴 — 板金店ギャップ

**保険修理は板金塗装店で発生する。コーティング店には保険案件が来ない。**

- Ledra の 12 店舗はコーティング・PPF 中心。→ **保険 PoC に使える案件が構造的にゼロ**。
- 堀越確認: **12 店舗に鈑金店は含まれていない。**
- 含意: **いまの Ledra には保険修理の記録が 1 件もない。** リーフレットに書いた「修理案件の確認工数削減」は、現時点では検証すらできない（Phase 0 の対照実験に使う案件そのものが存在しない）。

**PoC の前提条件は「店舗数」ではなく「保険修理を扱う板金店の数」。** 必要なのは 1,000 店ではなく **10〜20 店**。ここが決定的に違う。

## 3. 「保険会社の力を借りる」の正しい中身

依頼の中身を取り違えると断られる。

| | 依頼 | 相手のコスト | 結果 |
|---|---|---|---|
| ❌ | 「Ledra を広めるのを手伝ってください」 | メリットなし | 断られる |
| ✅ | 「御社の提携工場を 3〜5 社、紹介してください」 | ほぼゼロ（実験のためだけ） | 通りやすい |

損保は指定工場・提携工場のネットワークを持つ。「この地域の提携先 3 社に試してもらえませんか」と言えるのは保険会社だけ。**これが"扉"の本当の意味で、しかも極めて小さい依頼。**

## 4. いまのデータで今日から成立する用途 — 事故前状態の証明

> ※この節の効き目は **推論**。実際に査定現場でどれだけ揉めているかは堀越の肌感で要確認。食い違えば組み直す。

コーティング・PPF の施工記録には、**保険会社が絶対に持っていないデータ**が入っている — **事故前の車体状態**。コーティング店は施工前に必ず全周を撮影し、それが時刻固定で残っている。

査定で最も時間を取られ、かつ揉めるのは **既存損傷と事故損傷の切り分け**。

```
現状：事故後の写真しかない
      → 「この傷は前からあったのでは?」と言っても証明できない
      → 調査に時間がかかる／あるいは払わなくていいものを払う

Ledra があると：
      施工日に撮影された全周写真（時刻固定・改ざん不可）
      → 事故前の状態が一意に確定する
      → 切り分けが即座に終わる
```

保険会社は事故前の車の写真を体系的に持っていない（撮る機会がない）。**事故と無関係なタイミングで全周を撮っているのはコーティング店だけ = 構造的に Ledra にしかないデータ。**

## 5. 書き直した PoC 設計（3 段）

```
Phase 0 ── 机上の対照実験（2週間・案件20〜30件）
  査定担当者3〜5名に、同じ案件をLedraあり/なしで確認いただき所要時間を計測
  → 「15分削減」が出るかを判定。出なければPoC中止で構わない
  ※板金店ゼロのため、この工数削減Phase 0の案件は保険会社側から出してもらう設計に変える必要がある
    （自前のコーティング記録は保険修理案件ではないため対照実験の題材にならない）

Phase 1 ── 実案件での並行運用（2ヶ月）
  提携板金工場3〜5社にLedraを導入 ← ここだけ、ご紹介をお願いする
  その工場からの修理案件で、通常フローと並行してLedra記録を参照
  → 実運用での削減時間・見積一致率を測定

Phase 2 ── 不正検知の検証（Phase 1の結果次第）
  ここで初めて母数が必要。対象工場を拡大してから着手
```

**Phase 0 が効く。**「まず 2 週間、担当者の時間だけください。効果が出なければそこで終わりで結構です」— 断る理由がほぼない。Phase 0 を通過した時点で相手は当事者になっている。

## 6. 3 つの進み方（A / B / C）

| | 内容 | 保険PoCまでの時間 | リスク |
|---|---|---|---|
| **A** | 事故前状態証明で先に価値を出す | すぐ | 工数削減より訴求が小さい |
| **B** | 自力で板金店を 3 社入れてから保険へ | 3〜6ヶ月 | 展示会の機会を逃す |
| **C** | 保険会社に提携板金工場の紹介を頼む | 6〜12ヶ月 | 実績ゼロの相手に紹介はしづらい |

**推奨は A＋B 併走。**

- **A で今日、会話を始める。**「事故前の状態が確定できる記録があります。使ってみませんか」なら板金店ゼロでも成立。保険会社のコストもほぼゼロ（既存案件で照会してみるだけ）。
- **並行して B。** 堀越は業界の人なので板金店の知り合いはいるはず。3 社入れば C を頼むときの説得力が変わる（「うちには板金店がありません」→「3 社入っています。御社の提携先も加えさせてください」）。
- **C を最初に頼むのは順序が逆。** 実績ゼロの相手に提携先を紹介するのは保険会社にとってリスクが高すぎる。

## 7. リーフレットの直し方 — 時間軸で 2 段に分ける

いまの構成は「工数削減 3.2 万円／件」が主役だが、これは今すぐ検証できない（試算値。`3.2万円/件`・`1件15分で年37億円相当` はいずれも **未検証の試算**）。時間軸で分ける:

```
【いま、できること】
  事故前の車体状態を、時刻が固定された写真で証明する
  → コーティング・PPF施工車が対象。既存の12店舗のデータで即日照会可能
  → 既存損傷と事故損傷の切り分けに使えます

【次に、ご一緒したいこと】
  修理案件の確認工数削減（試算: 1件15分 → 年37億円相当・いずれも要検証）
  → 板金塗装工場の参加が前提。御社の提携先をご紹介いただけると加速します
```

あわせて **「板金店の紹介」を明示的なお願い** にする（現状は曖昧）。工数削減の ROI 試算は捨てず"次のステージ"として残す。
