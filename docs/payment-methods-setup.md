# 決済手段の申請と確認の手順

店頭・請求書で使える決済手段を増やすための手順書。**加盟店がやること**と、
**Ledra 側（代表）が本番前に確かめること**を分けて書く。

前提として、Ledra は決済手段の利用を**強制しない**。使いたい手段だけ申請すれば
よく、申請しなくてもカード決済は今までどおり使える。

---

## 1. 加盟店がやること

### 1-1. Stripe を接続する（カード・PayPay・Alipay・WeChat Pay・コンビニ・銀行振込）

1. Ledra の `設定 → 決済（Stripe Connect）` で **「Stripeアカウントを接続」**。
2. その前に **「一緒に申請する決済手段（任意）」** のチェックが出る。ここで選んだ
   手段は、Stripe のオンボーディングが**同じ入力フローで**審査に必要な情報を集める。
   - 選ばなくても接続できる。後から Stripe のダッシュボードでいつでも申請できる。
   - 選ぶと入力項目が増える。使う予定のあるものだけ選べばよい。
3. Stripe の画面で事業者情報・本人確認・銀行口座を入力する。
4. 戻ってきて `課金受付: 有効` `入金: 有効` になれば完了。

**この時点で使えるもの**: カード / Apple Pay / Google Pay（＝カード扱い）。

### 1-2. Stripe 側で決済手段を有効化する

PayPay・Alipay・WeChat Pay・コンビニ払い・銀行振込は、Stripe ダッシュボードの
**設定 → 決済手段**から有効化（申請）する。審査は手段ごとに Stripe が行う。

- **PayPay**: 申請が要る（Stripe の記載では数週間かかる場合がある）。
- **Alipay / WeChat Pay**: インバウンド客が多い店向け。
- **コンビニ払い / 銀行振込**: 請求書の決済リンクにだけ出る。**レジには出さない**
  （入金確定が後日なので、レジが完了を待ち続けてしまうため）。

Ledra 側の設定は不要。**有効化された手段は、次の会計から自動で出る。**
使えない手段があっても会計は止まらない（その手段だけ出なくなる）。

### 1-3. Square を接続する（d払い・楽天ペイ・au PAY・メルペイ を使う場合）

これら4ブランドは Stripe が対応していないため Square 経由になる。

1. Square のアカウントを作る。**QR コード決済の申請はアカウント作成の
   オンボーディングの中で案内される**（主要7ブランドが1回の申請で通る）。
2. Ledra の `設定 → 外部サービス連携` で **Square を接続**。
   - 既に接続済みの場合も、**一度切断して繋ぎ直す**。決済を起こすための権限
     （`PAYMENTS_WRITE` / `DEVICE_CREDENTIAL_MANAGEMENT`）を後から足したため、
     古い接続では決済を起こせない。
3. Square 端末を使う場合は、`設定 → 決済（Square）` の
   **「Square 端末を接続する」**でコードを発行し、端末に入力する。

**端末があるとき**: レジで「QR決済」を選ぶと端末にマルチブランド QR が出る。
店員は Ledra から移動しない。

**端末が無いとき**: Square の QR は対面決済専用でアプリか端末にしか出せないため、
Square アプリで会計 → Ledra に戻って **「Ledra に取り込む」**。直近30分・同額・
同店舗の QR 決済を引き当てて記帳する。同額の会計が重なって特定できないときは
記帳しない（取り違えを避けるため）。その場合は現金などと同じ手入力で記録する。

---

## 2. Ledra 側（代表）が本番前に確かめること

実装は入っているが、**外部 API を1回も叩いていない**項目がある。ここを1回ずつ
通せば確定する。失敗しても既存の会計は落ちない作りだが、「使える」と案内する前に
確認が要る。

### 2-1. Stripe: PayPay / Alipay / WeChat Pay が実際に出るか【未検証】

1. Stripe の**テスト環境**で、対象の決済手段を有効化する。
2. Ledra のレジで金額を入れ、支払方法「カード」を選んで QR を出す。
3. **確認**: QR を開いた Stripe の画面に、有効化した手段が並ぶか。
   Ledra の案内文（「カード / Apple Pay / Google Pay / PayPay …が使えます」）が
   実際の提示内容と一致しているか。
4. **同じテストで**、その手段で払った直後にレジが「決済完了」になるか。
   - ならない場合、その手段は後日確定（非同期）ということ。レジから外す必要がある。
5. 出ない場合はログに `pos checkout: ... dropping payment option rejected by Stripe`
   が出る。どの手段が外されたかが記録されるので、それを見れば原因が分かる。

### 2-2. Stripe: 一緒に申請した決済手段が反映されるか【未検証】

1. **新規**テナントで Stripe を接続し、チェックを付けて申請する
   （既存の接続には効かない。作成時にしか要求できないため）。
2. **確認**: Stripe のオンボーディングで、その手段の審査に必要な入力が増えるか。
3. `paypay_payments` という capability 名が正しいかはここで確定する。違っていた
   場合は、その要求だけ外れてアカウントは作られ、ログに
   `stripe: dropping payment option rejected by Stripe`（scope: capability）が残る。

### 2-3. Square: 端末・引き当て【未検証】

Square の **Sandbox（日本ロケーション）** で通す。

1. **デバイスコード**: `設定 → 決済（Square）` で「Square 端末を接続する」→
   コードが出るか。端末に入力して「入力が終わったら確認」で `PAIRED` になるか。
2. **端末決済**: レジで「QR決済」を選ぶ → 端末にマルチブランド QR が出るか
   （`payment_type: "QR_CODE"` が Sandbox で通るか）。
3. **記帳**: 決済後、Ledra に「QR決済」として売上が立つか。金額が Square の実額と
   一致するか。同じ会計をもう一度記録しようとしても2件にならないか
   （`payments.square_payment_id` の一意インデックス）。
4. **引き当て**（端末なしの経路）: Square アプリで会計 → Ledra で「取り込む」→
   記帳されるか。**同額の会計を2件続けて**作り、2件目が「特定できない」で
   止まることも確認する（ここが緩いと売上を取り違える）。

### 2-4. 事前に確認しておくと早いこと

- Square の QR コード決済の申請が通っているか（申請1回で7ブランド、店舗ごと）。
- Square 端末を買うかどうか。**「店員が Ledra から移動しない」の条件は端末**で、
  買わない場合はアプリへの移動が残る。
- Stripe の PayPay 申請にかかる実際の期間（Stripe の記載は「数週間」）。

## 3. うまくいかないときの見どころ

| 症状                                           | 見るところ                                                                                     |
| ---------------------------------------------- | ---------------------------------------------------------------------------------------------- |
| レジに PayPay 等が出ない                       | ログの `dropping payment option rejected by Stripe`。Stripe 側で有効化されていない可能性が高い |
| Square の会計で「Square の接続が切れています」 | 権限追加後に繋ぎ直していない。設定から切断 → 再接続                                            |
| 「取り込む」で `square_payment_ambiguous`      | 同額の会計が短時間に複数ある。特定できないので記帳していない（取り違え防止）                   |
| 「取り込む」で `square_payment_not_found`      | 直近30分に同額の**QR決済**が無い。カード・現金で会計している場合はこの経路では取り込めない     |
| 決済は済んだのに記録が無い                     | レジの「記録をやり直す」を押す。決済 ID で冪等になっているので二重計上にはならない             |
